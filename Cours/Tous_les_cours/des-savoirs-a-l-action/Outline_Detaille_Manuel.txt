## Fonction UCKK dominante

## Rôle du chapitre

Ce chapitre sert à :

* présenter le guide ;

# 1. Situer — Pourquoi ce guide existe

## 1.1 Idée centrale

Présenter le guide comme une méthode pour transformer une situation, un besoin ou un dossier existant en piste d’action responsable.

Formulation à développer :

> Ce guide propose une méthode pour passer d’une situation confuse à une compréhension plus claire, puis d’une compréhension plus claire à une action prudente, documentée et révisable.

## 1.2 Contexte de départ

Expliquer que beaucoup de situations échouent non pas parce qu’il n’y a aucune ressource, mais parce que :

* les informations sont dispersées ;
* les personnes concernées ne sont pas assez écoutées ;
* les ressources existantes sont invisibles ;
* les solutions arrivent trop vite ;
* les impacts sont mal prévus ;
* les dossiers s’accumulent sans devenir actionnables ;
* les apprentissages ne sont pas gardés en mémoire.

## 1.3 Ce que le guide cherche à former

Le guide apprend à :

* observer ;
* écouter ;
* inventorier ;
* distinguer ;
* choisir ;
* agir ;
* corriger ;
* mémoriser ;
* transmettre prudemment.

## 1.4 Phrase d’orientation

À placer dans le texte :

> Ce guide n’enseigne pas comment imposer une solution. Il enseigne comment préparer une action responsable à partir de ressources, d’observations, de choix prudents et de traces utiles.

---

# 2. Distinguer — Ce que le guide est et n’est pas

## 2.1 Ce que le guide est

Le guide est :

* un guide d’apprentissage ;
* une méthode de clarification ;
* une méthode de préparation à l’action ;
* un outil de réflexion et de production ;
* une aide à la décision prudente ;
* une manière de transformer des informations existantes en pistes utiles ;
* une démarche qui garde trace des apprentissages.

## 2.2 Ce que le guide n’est pas

Clarifier explicitement :

* pas un manuel sur les cultures autochtones ;
* pas un protocole universel ;
* pas un outil d’extraction des savoirs ;
* pas une procédure pour décider à la place des personnes concernées ;
* pas un document kOA ;
* pas un manuel technique sur l’IA ;
* pas une méthode qui remplace les protocoles locaux ;
* pas une autorisation de recueillir ou réutiliser des informations sensibles.

## 2.3 Distinctions importantes à annoncer

Présenter les premières distinctions du guide :

| À ne pas confondre           | Pourquoi c’est important                                  |
| ---------------------------- | --------------------------------------------------------- |
| Information / connaissance   | Une information doit être située et vérifiée.             |
| Écoute / extraction          | Écouter ne donne pas automatiquement le droit d’utiliser. |
| Hypothèse / fait             | Une hypothèse doit rester vérifiable.                     |
| Solution / choix responsable | Une solution doit être comparée et justifiée.             |
| Action / impact              | Une action produit des effets à prévoir.                  |
| Archive / mémoire utile      | Une archive doit être organisée pour servir sans nuire.   |

## 2.4 Point de vigilance

Inclure une phrase de prudence :

> Tout ce qui existe, se dit ou se trouve dans un dossier n’est pas automatiquement utilisable, partageable ou réutilisable.

Cette prudence est directement soutenue par la bibliographie : Smith, Wilson, Kovach, Tuck & Yang, EPTC 2, OCAP® et CARE insistent sur la non-extraction, la relation, le consentement, le contexte, la gouvernance et la responsabilité.

# 3. Transformer — La transformation centrale du guide

## 3.1 Schéma central

Présenter la chaîne de transformation :

```text
information dispersée
→ compréhension prudente
→ choix justifié
→ action responsable
→ mémoire utile
```

## 3.2 Explication simple

Développer chaque passage :

### Information dispersée → compréhension prudente

L’étudiant apprend à inventorier les ressources, écouter, observer et distinguer les faits des hypothèses.

### Compréhension prudente → choix justifié

L’étudiant apprend à ne pas courir vers la première solution. Il explore plusieurs options, les compare et choisit selon le temps disponible.

### Choix justifié → action responsable

L’étudiant transforme une décision en premier geste concret, avec responsabilités visibles et impacts prévus.

### Action responsable → mémoire utile

L’étudiant garde une trace de ce qui a été appris, corrigé, transmis ou protégé.

## 3.3 Lien avec le standard UCKK

Expliquer brièvement :

> Le guide suit le standard UCKK : orienter, situer, distinguer, transformer, produire, évaluer, mémoriser, projeter et référencer.

Ne pas développer le standard au complet dans l’introduction. Simplement l’annoncer.

## 3.4 Phrase à inclure

> Une démarche responsable ne saute pas directement du problème à la solution. Elle passe par les ressources, l’écoute, la clarification, l’exploration, le choix, l’action et la mémoire.

````markdown
## 2.0 Objectifs du chapitre

- reconnaître qu’une situation ne se résume pas à ses problèmes ;
- repérer les ressources déjà présentes dans un milieu ;
- distinguer manque, besoin, capacité, potentiel et urgence ;
- reformuler une situation sans réduire les personnes à leurs difficultés ;
- produire une première description orientée vers les ressources.

---

## 2.1 Situer — Le réflexe de commencer par les problèmes

### Idée centrale

Beaucoup de démarches commencent par une question apparemment évidente :
 
> Quel est le problème ?

Cette question peut être utile, mais elle devient insuffisante si elle est posée seule. Elle peut orienter tout le regard vers les déficits, les manques, les blessures, les urgences et les dysfonctionnements.

### À développer

Expliquer que commencer uniquement par le problème peut produire plusieurs effets :

- on voit les déficits avant les capacités ;
- on décrit les personnes à partir de ce qui leur manque ;
- on sous-estime les savoirs déjà présents ;
- on ignore les relations locales ;
- on propose trop vite des solutions extérieures ;
- on oublie que le milieu possède déjà des forces, pratiques, ressources et désirs.

### Renversement proposé

Introduire la question centrale du chapitre :

> Avant de demander “qu’est-ce qui manque ?”, demander “qu’est-ce qui existe déjà ?”

### Référence à mobiliser

Kretzmann & McKnight sont la référence principale ici : leur approche du développement communautaire fondé sur les ressources invite à identifier les actifs d’une communauté plutôt que de commencer uniquement par ses besoins ou déficits. La bibliographie commentée présente cette référence comme centrale pour l’inventaire des ressources. :contentReference[oaicite:1]{index=1}

---

## 2.2 Distinguer — Problème, contexte, manque, ressource

### Idée centrale

Le chapitre doit apprendre à l’étudiant à ne pas confondre plusieurs réalités.

### Distinctions à enseigner

| Distinction | Explication |
|---|---|
| Problème / contexte | Le problème est ce qui dérange ; le contexte est ce qui permet de comprendre pourquoi cela arrive. |
| Manque / ressource | Un manque indique ce qui n’est pas disponible ; une ressource indique ce qui peut soutenir une action. |
| Vulnérabilité / capacité | Une personne peut vivre une difficulté tout en portant des savoirs, compétences ou relations importantes. |
| Besoin / potentiel | Un besoin demande une réponse ; un potentiel indique une possibilité à développer. |
| Urgence visible / force invisible | Ce qui presse attire l’attention ; ce qui soutient déjà le milieu peut rester moins visible. |

### Point de vigilance

Ne pas nier les problèmes.  
Le but n’est pas de remplacer une lecture des difficultés par une lecture naïve des forces. Le but est de tenir les deux ensemble :

> voir les difficultés sans effacer les capacités.

### Référence à mobiliser

Eve Tuck est utile ici : elle critique les recherches centrées seulement sur les dommages, qui risquent de réduire les communautés à leurs blessures. La bibliographie commentée la présente comme une référence importante pour éviter les approches centrées uniquement sur le déficit. :contentReference[oaicite:2]{index=2}

## 2.3 Transformer — Changer le regard avant d’agir

### Idée centrale

La transformation du chapitre n’est pas encore une action extérieure.  
C’est d’abord une transformation du regard.

```text
Voir seulement le problème
→ reconnaître le contexte
→ identifier les ressources
→ ouvrir des possibilités d’action plus justes
````

### À développer

Expliquer que deux descriptions d’une même situation peuvent produire des effets différents.

Une description centrée uniquement sur les problèmes peut mener à :

* une solution imposée ;
* une posture de sauveur ;
* une lecture déficitaire ;
* une faible confiance envers les personnes concernées.

Une description centrée aussi sur les ressources peut mener à :

* une action plus située ;
* une meilleure reconnaissance des personnes ;
* une solution construite à partir de ce qui existe déjà ;
* une démarche plus respectueuse.

### Formule à intégrer

> La première transformation n’est pas de changer la situation. C’est de changer la manière de la regarder.

## 2.4 Produire — Exercice de double description

### But de l’exercice

Faire sentir concrètement la différence entre une description par les manques et une description par les ressources.

### Consigne

À partir d’une situation choisie, écrire deux descriptions courtes.

#### Description A — Centrée sur les problèmes

Décrire la situation en répondant seulement à ces questions :

* Qu’est-ce qui ne fonctionne pas ?
* Qu’est-ce qui manque ?
* Qu’est-ce qui est urgent ?
* Qu’est-ce qui bloque ?
* Qu’est-ce qui inquiète ?

#### Description B — Centrée sur les ressources

Décrire la même situation en répondant à ces questions :

* Qu’est-ce qui existe déjà ?
* Qui possède des compétences utiles ?
* Quelles relations peuvent aider ?
* Quels lieux, outils, expériences ou documents sont disponibles ?
* Qu’est-ce qui a déjà été tenté ?
* Quelles forces sont moins visibles ?

### Tableau d’exercice

| Élément              | Description centrée sur les problèmes | Description centrée sur les ressources |
| -------------------- | ------------------------------------- | -------------------------------------- |
| Personnes concernées |                                       |                                        |
| Situation observée   |                                       |                                        |
| Ce qui manque        |                                       |                                        |
| Ce qui existe déjà   |                                       |                                        |
| Risques              |                                       |                                        |
| Capacités présentes  |                                       |                                        |
| Première impression  |                                       |                                        |
| Possibilité ouverte  |                                       |                                        |

### Questions de comparaison

Après avoir rempli le tableau, l’étudiant répond :

* Quelle description donne le plus envie d’agir vite ?
* Quelle description donne le plus envie de consulter ?
* Quelle description reconnaît le mieux les personnes concernées ?
* Quelle description risque de produire une solution extérieure ?
* Quelle description ouvre le plus d’options ?
* Qu’est-ce que la deuxième description révèle que la première cachait ?

## 2.5 Retenir — Points de vigilance

### Erreurs fréquentes

* confondre ressources et solutions ;
* croire que reconnaître les ressources minimise les problèmes ;
* décrire les personnes seulement par leurs difficultés ;
* oublier les ressources relationnelles ;
* oublier les ressources documentaires ou dormantes ;
* supposer qu’une ressource est disponible simplement parce qu’elle existe ;
* nommer une ressource sans vérifier qui peut l’utiliser ou l’autoriser.

### Points de vigilance

Une ressource peut être :

* présente mais inaccessible ;
* utile mais sensible ;
* disponible seulement avec permission ;
* portée par une personne déjà surchargée ;
* liée à un lieu, une saison, une relation ou un protocole ;
* dormante parce qu’elle n’a pas été activée ou transmise.

### Phrase clé

> Une communauté ne doit pas être décrite seulement par ses manques.

### Phrase complémentaire

> Reconnaître les ressources ne nie pas les problèmes ; cela empêche de réduire la situation à ses problèmes.

# 2. Distinguer

## 2.1 Distinction principale

Distinguer :

```text
problème ≠ absence totale de ressources
besoin ≠ solution
ressource ≠ permission d’usage
information disponible ≠ information utilisable
personne compétente ≠ personne disponible
document existant ≠ document validé
```

Cette section est importante : elle évite que l’étudiant traite toute ressource repérée comme immédiatement mobilisable.

## 2.2 Définition de “ressource”

Définition simple :

> Une ressource est ce qui existe déjà et peut aider à comprendre, orienter ou soutenir une action.

Mais ajouter immédiatement :

> Une ressource peut être présente sans être accessible. Elle peut être utile sans être partageable. Elle peut être connue sans être mobilisable.

## 2.3 Les dix types de ressources

### 1. Ressources communautaires

Ce qui appartient au milieu collectif.

Exemples :

* associations ;
* comités ;
* lieux collectifs ;
* réseaux d’entraide ;
* initiatives existantes ;
* personnes reconnues par le milieu ;
* pratiques collectives ;
* événements réguliers.

Question-guide :

> Qu’est-ce que la communauté fait déjà par elle-même ?

---

### 2. Ressources individuelles

Ce que des personnes portent.

Exemples :

* compétences ;
* expériences ;
* savoir-faire ;

| local             | capacité d’organisation |

Phrase à retenir :

## 2.5 Ressource, accès, permission

Distinguer trois choses :

| Question                         | Sens                  |
| -------------------------------- | --------------------- |
| Est-ce que la ressource existe ? | Présence              |
| Peut-on y accéder ?              | Accessibilité         |
| A-t-on le droit de l’utiliser ?  | Permission / autorité |

Cette distinction est essentielle dans un contexte communautaire ou autochtone. La bibliographie insiste sur la non-extraction, le consentement, les relations, les responsabilités et la souveraineté des données ou savoirs.

# 3. Transformer

## 3.1 Opération centrale du chapitre

L’étudiant apprend à transformer une situation vague en carte organisée.

```text
situation vague
→ liste de ressources
→ catégories
→ porteurs
→ conditions d’accès
→ limites
→ précautions
```

## 3.2 Étapes de transformation

### Étape 1 — Nommer la situation

Écrire une phrase simple :

> La situation étudiée est : ______

### Étape 2 — Lister sans classer

Pendant quelques minutes, écrire toutes les ressources possibles sans les organiser.

But : éviter de censurer trop vite.

### Étape 3 — Classer par type

Reprendre la liste et classer les ressources dans les catégories :

* communautaire ;
* individuelle ;
* relationnelle ;
* logistique ;
* matérielle ;
* territoriale ;
* culturelle ;
* institutionnelle ;
* documentaire ;
* dormante.

### Étape 4 — Identifier le porteur

Pour chaque ressource, demander :

* qui la porte ?
* qui la connaît ?
* qui peut en parler ?
* qui peut l’autoriser ?
* qui peut la mobiliser ?

### Étape 5 — Clarifier l’accès

Demander :

* comment y accéder ?
* à quelles conditions ?
* avec quelle permission ?
* par quel intermédiaire ?
* dans quel délai ?

### Étape 6 — Nommer les limites

Demander :

* est-ce sensible ?
* est-ce à vérifier ?
* est-ce dépassé ?
* est-ce confidentiel ?
* est-ce incomplet ?
* est-ce disponible mais non utilisable ?
* est-ce lié à un protocole local ?

### Étape 7 — Identifier les ressources à approfondir

Choisir trois ressources qui méritent une vérification ou une conversation supplémentaire.

## 3.3 Erreurs fréquentes

Inclure une courte liste :

* confondre ressource et solution ;
* oublier les ressources relationnelles ;
* ne voir que les ressources matérielles ;
* traiter une information comme librement utilisable ;
* oublier les limites d’accès ;
* écrire “la communauté” sans identifier les personnes ou groupes réels ;
* confondre disponibilité et permission ;
* ignorer les dossiers dormants ;
* ne pas noter ce qui doit être vérifié.

## 3.4 Point de vigilance

Formulation recommandée :

> Une ressource n’est pas seulement quelque chose qu’on peut prendre. C’est quelque chose qui existe dans un contexte, avec des personnes, des relations, des limites et parfois des permissions.

Cette formulation s’appuie bien sur Wilson, qui pense le savoir comme relation et responsabilité, et sur les références méthodologiques autochtones de la bibliographie.

# 5. Retenir

## 5.1 Phrase clé

## 5.2 Trois idées à retenir

1. Une situation ne se comprend pas seulement par ses problèmes.
2. Une ressource peut être présente sans être accessible ou utilisable.
3. Les ressources invisibles — confiance, relations, mémoire, savoir-faire — peuvent être aussi importantes que les ressources matérielles.

* commencer par la solution ;
* oublier les personnes qui portent les ressources ;
* ignorer les ressources relationnelles ;

* ne pas noter les précautions ;
* oublier les ressources dormantes.

# Chapitre 04 — Écouter avec attention

## Fonction UCKK dominante

```text
Distinguer → Transformer
```

## Transformation centrale du chapitre

```text
parole reçue
→ observation prudente
→ distinction entre parole, contexte et interprétation
→ questions ouvertes
→ compréhension à vérifier
```

## Objectif du chapitre

À la fin du chapitre, l’étudiant doit être capable de :

* écouter sans conclure trop vite ;
* distinguer ce qui est dit de ce qu’il interprète ;
* observer les gestes, silences et contextes sans leur imposer un sens immédiat ;
* reconnaître qu’il ne comprend jamais tout ;
* formuler des questions ouvertes ;
* respecter les limites, silences et refus ;
* produire une fiche d’écoute utilisable pour la suite du travail.

---

# 4.1 Situer — L’écoute comme pratique active

## Idée centrale

L’écoute n’est pas une attente passive. C’est une pratique active qui demande attention, retenue, humilité et méthode.

## Contenu à développer

Expliquer que, dans une situation réelle, les personnes ne transmettent pas seulement des informations. Elles transmettent aussi :

* des expériences ;
* des hésitations ;
* des émotions ;
* des silences ;
* des gestes ;
* des priorités implicites ;
* des limites ;
* des relations au contexte.

Le chapitre doit insister sur cette idée :

> Les paroles, gestes, silences et contextes ont une profondeur qu’on ne peut pas saisir immédiatement.

## Point pédagogique

L’étudiant doit apprendre à ralentir. Il ne doit pas écouter seulement pour répondre, corriger, conseiller ou classer. Il doit écouter pour comprendre ce qui peut être compris, et reconnaître ce qui reste hors de portée.

## Références mobilisées

* **Rogers & Farson** : écoute active.
* **Wilson** : savoir relationnel, responsabilité, contexte.
* **Kovach** : conversation, récit, savoir situé.

Voir la bibliographie commentée pour les références complètes. 

---

# 4.2 Distinguer — Entendre n’est pas écouter

## Idée centrale

Entendre est recevoir un son ou une parole. Écouter demande un effort de compréhension.

## Distinctions à enseigner

| Confusion à éviter             | Distinction à faire                                   |
| ------------------------------ | ----------------------------------------------------- |
| Entendre = écouter             | Entendre est passif ; écouter est actif               |
| Parole = vérité complète       | Une parole est importante, mais elle doit être située |
| Silence = accord               | Un silence peut signifier plusieurs choses            |
| Refus = obstacle               | Un refus peut être une limite légitime                |
| Observation = conclusion       | Observer n’autorise pas à conclure immédiatement      |
| Interprétation = compréhension | Une interprétation doit être vérifiée                 |

## Contenu à développer

Expliquer que l’étudiant peut entendre correctement une phrase et quand même mal comprendre la situation. L’écoute attentive exige de suspendre les conclusions immédiates.

## Phrase à intégrer

> On peut entendre toutes les paroles et manquer le sens de la situation.

---

# 4.3 Distinguer — Parole, geste, silence, contexte

## Idée centrale

La parole n’est jamais seule. Elle existe dans un contexte.

## Quatre dimensions à observer

### 1. La parole

Ce qui est dit explicitement.

Exemples :

* besoins nommés ;
* frustrations ;
* souvenirs ;
* demandes ;
* priorités ;
* contradictions ;
* répétitions.

### 2. Le geste

Ce qui accompagne ou nuance la parole.

Exemples :

* hésitations ;
* regard ;
* posture ;
* mouvement ;
* retrait ;
* tension ;
* fatigue.

### 3. Le silence

Ce qui n’est pas dit, ou ne peut pas être dit.

Exemples :

* refus de répondre ;
* gêne ;
* prudence ;
* protection d’un savoir ;
* manque de confiance ;
* besoin de temps.

### 4. Le contexte

Ce qui entoure la parole.

Exemples :

* lieu ;
* relation entre les personnes ;
* histoire de la situation ;
* présence d’autres personnes ;
* pression institutionnelle ;
* moment choisi ;
* contraintes pratiques.

## Vigilance

Ne pas surinterpréter les gestes ou silences. Ils signalent qu’il faut ralentir, pas qu’on possède déjà la réponse.

## Phrase à retenir

> Un silence n’est pas un vide à remplir. C’est parfois une limite à respecter.

---

# 4.4 Distinguer — Le refus comme information et comme limite

## Idée centrale

Une personne ou une communauté peut refuser de répondre, de partager, de participer ou de valider une interprétation.

## Contenu à développer

Le refus ne doit pas être traité comme un simple obstacle à contourner. Il peut indiquer :

* une limite de confiance ;
* une information sensible ;
* un savoir non partageable ;
* un désaccord ;
* un besoin de temps ;
* une autorité qui n’appartient pas à l’étudiant ;
* une histoire de collecte ou d’extraction.

## Distinctions à poser

| Refus mal compris               | Refus bien compris                                      |
| ------------------------------- | ------------------------------------------------------- |
| “La personne bloque le travail” | “Une limite a été posée”                                |
| “Il faut insister”              | “Il faut respecter et documenter la limite”             |
| “L’information manque”          | “L’information n’est peut-être pas disponible pour moi” |
| “Je dois obtenir une réponse”   | “Je dois reconnaître ce qui ne peut pas être partagé”   |

## Référence mobilisée

* **Audra Simpson** : le refus peut être une position politique, relationnelle ou méthodologique légitime.

## Phrase à retenir

> Tout ce qui peut être demandé ne doit pas nécessairement être partagé.

---

# 4.5 Transformer — De la parole reçue à l’observation prudente

## Idée centrale

L’écoute devient utile lorsqu’elle produit une trace prudente, sans transformer trop vite les paroles en conclusions.

## Opération à enseigner

```text
parole reçue
→ note exacte
→ observation
→ contexte
→ interprétation possible
→ question ouverte
→ vérification nécessaire
```

## Méthode en six étapes

1. Noter quelques paroles exactes.
2. Noter ce qui a été observé.
3. Décrire le contexte.
4. Écrire ce qu’on croit comprendre.
5. Identifier ce qu’il faut vérifier.
6. Nommer ce qu’on ne comprend pas encore.

## Vigilance

L’étudiant doit éviter de transformer immédiatement :

* une phrase en diagnostic ;
* un geste en preuve ;
* un silence en consentement ;
* une émotion en conclusion ;
* une impression en fait.

Cette logique rejoint le principe de transformation contrôlée : une contribution ne devient pas automatiquement connaissance ; chaque passage demande une structure, une trace ou une vérification. 

---

# 4.6 Produire — Tableau d’écoute attentive

## Tableau principal

| Ce qui est dit | Ce qui est observé | Contexte | Ce que je crois comprendre | Ce que je dois vérifier | Ce que je ne comprends pas encore |
| -------------- | ------------------ | -------- | -------------------------- | ----------------------- | --------------------------------- |
|                |                    |          |                            |                         |                                   |

## Consignes d’utilisation

L’étudiant remplit le tableau après une écoute, une entrevue, une discussion, une observation ou une lecture de témoignage.

Il doit éviter :

* d’écrire seulement des conclusions ;
* de gommer les incertitudes ;
* de transformer les paroles en résumé trop propre ;
* de supprimer les contradictions ;
* de rendre public ce qui ne doit pas l’être.

## Variante courte

| Parole exacte | Observation | Interprétation possible | Question ouverte |
| ------------- | ----------- | ----------------------- | ---------------- |
|               |             |                         |                  |

## Variante avancée

| Élément observé | Ce que cela pourrait vouloir dire | Autres interprétations possibles | Vérification nécessaire | Risque de mauvaise lecture |
| --------------- | --------------------------------- | -------------------------------- | ----------------------- | -------------------------- |
|                 |                                   |                                  |                         |                            |

# 4.7 Produire — Mini-exercice d’écoute

## Titre de l’exercice

**Écouter sans conclure**

## Durée suggérée

30 à 45 minutes.

## Consigne

Écouter une personne décrire une situation, ou lire un court témoignage fourni par l’enseignant. Ensuite, produire une fiche d’écoute.

## L’étudiant doit noter

* trois paroles exactes ;
* deux observations ;
* deux éléments de contexte ;
* deux interprétations possibles ;
* trois questions ouvertes ;
* une limite de partage ;
* une chose qu’il ne comprend pas encore.

## Production attendue

Une fiche d’écoute attentive d’une page.

## Critères de réussite

La fiche est réussie si :

* les paroles ne sont pas déformées ;
* les observations sont séparées des interprétations ;
* les incertitudes sont visibles ;
* les questions restent ouvertes ;
* les limites de partage sont respectées ;
* l’étudiant ne prétend pas avoir tout compris.

## Variante en équipe

En petits groupes :

1. une personne raconte une situation fictive ou non sensible ;
2. une personne écoute ;
3. une personne observe les gestes et le contexte ;
4. le groupe compare ensuite les différences entre parole entendue, observation et interprétation.

---

# 4.8 Erreurs fréquentes

## Erreur 1 — Conclure pendant que l’autre parle

L’étudiant prépare déjà sa réponse au lieu d’écouter.

## Erreur 2 — Résumer trop vite

Le résumé efface les nuances, les hésitations ou les contradictions.

## Erreur 3 — Confondre empathie et compréhension complète

Être touché par une parole ne signifie pas qu’on comprend toute la situation.

## Erreur 4 — Traiter le silence comme un accord

Le silence peut être prudence, fatigue, refus, gêne ou protection.

## Erreur 5 — Transformer une observation en diagnostic

Un geste observé ne suffit pas à conclure.

## Erreur 6 — Forcer la cohérence

Les paroles humaines peuvent être contradictoires. La contradiction doit être notée avant d’être expliquée.

---

# 4.9 Retenir — Synthèse du chapitre

## Ce que l’étudiant doit retenir

* Écouter est une pratique active.
* Les paroles ne suffisent pas à elles seules.
* Les gestes, silences et contextes doivent être observés avec prudence.
* Un refus ou un silence peut être une limite légitime.
* Une interprétation doit rester vérifiable.
* Ne pas comprendre entièrement fait partie d’une démarche honnête.
* Une bonne écoute produit des questions, pas seulement des réponses.

## Phrase clé

> Pendant que quelqu’un parle, le travail n’est pas de conclure. Le travail est d’écouter.

## Phrase secondaire

> Une écoute responsable garde visible ce qui est dit, ce qui est observé, ce qui est interprété et ce qui reste incertain.

# 05. Distinguer faits, hypothèses et interprétations

## Fonction UCKK dominante

**Distinguer**

## Transformation centrale du chapitre

```text
notes confuses
→ énoncés classés
```

## Rôle du chapitre dans le manuel

Ce chapitre ferme la première grande phase du guide : **inventorier, écouter et comprendre**.

Après avoir reconnu les ressources et écouté avec attention, l’étudiant doit apprendre à ne pas mélanger :

* ce qui a été observé ;
* ce qui est supposé ;
* ce qui est interprété ;
* ce qui est décidé ;
* ce qui reste incertain.

Cette distinction est déjà centrale dans le tronc commun UCKK, qui forme les étudiants à distinguer **fait, hypothèse, interprétation, récit et décision**. 

---

# 05.1 Idée centrale du chapitre

## Message principal

Comprendre une situation ne veut pas dire avoir une opinion forte sur elle.
Comprendre commence par classer prudemment ce que l’on sait, ce que l’on croit savoir, ce que l’on interprète et ce qui reste à vérifier.

## Phrase d’ouverture possible

> Une grande partie des erreurs commence lorsqu’on confond ce qui est observé, ce qui est supposé, ce qui est interprété et ce qui est décidé.

## Objectif pédagogique

À la fin du chapitre, l’étudiant doit être capable de prendre des notes d’écoute ou d’observation et de les transformer en une **carte de compréhension**.

Cette carte ne donne pas encore une solution. Elle prépare seulement une base plus claire pour explorer des solutions dans la partie suivante.

---

# 05.2 Situer

## 05.2.1 Pourquoi cette distinction est nécessaire

Développer l’idée suivante :

Quand une situation est complexe, les personnes mélangent souvent plusieurs niveaux :

* elles voient quelque chose ;
* elles supposent pourquoi cela arrive ;
* elles donnent un sens à ce qu’elles voient ;
* elles décident parfois trop vite quoi faire ;
* elles oublient ce qui reste incertain.

Exemple simple :

> “Les jeunes ne viennent pas aux activités parce qu’ils ne sont pas intéressés.”

Cet énoncé contient peut-être :

* un fait : les jeunes ne viennent pas ;
* une hypothèse : ils ne sont pas intéressés ;
* une interprétation : l’activité n’a pas de valeur pour eux ;
* une décision implicite : il faudrait changer l’activité ;
* une incertitude : on ne sait pas encore pourquoi ils ne viennent pas.

## 05.2.2 Le lien avec l’écoute

Ce chapitre prolonge le chapitre précédent.

Écouter avec attention ne suffit pas.
Il faut ensuite éviter de transformer trop vite l’écoute en conclusion.

Lien à faire avec Rogers & Farson :

* l’écoute active demande de suspendre le jugement ;
* comprendre quelqu’un exige de ne pas réduire sa parole à ce que l’on croyait déjà savoir.

## 05.2.3 Le lien avec la non-extraction

Dans un contexte communautaire ou autochtone, mal classer l’information peut produire une forme d’extraction :

* on prend une parole située comme une vérité générale ;
* on retire une phrase de son contexte ;
* on transforme une expérience personnelle en donnée publique ;
* on interprète un silence comme une réponse ;
* on décide à partir d’un savoir qui n’était pas destiné à être utilisé ainsi.

Smith, Kovach et Wilson soutiennent ici une posture de prudence : les savoirs, les récits, les conversations et les relations ne doivent pas être réduits à de simples données disponibles.

# 05.3 Distinguer

## 05.3.1 Définitions principales

Inclure le tableau suivant.

| Terme              | Définition courte                | Question à poser                                             |
| ------------------ | -------------------------------- | ------------------------------------------------------------ |
| **Fait**           | Élément vérifiable               | Comment peut-on le vérifier ?                                |
| **Hypothèse**      | Possibilité à confirmer          | Qu’est-ce qui permettrait de la confirmer ou de l’infirmer ? |
| **Interprétation** | Sens donné à une situation       | Qui donne ce sens ? À partir de quel contexte ?              |
| **Décision**       | Orientation choisie après examen | Qui décide ? Sur quelle base ?                               |
| **Incertitude**    | Élément qui reste ouvert         | Que ne savons-nous pas encore ?                              |

## 05.3.2 Fait

### À expliquer

Un fait est un élément qui peut être vérifié par une source, une observation, un document, une mesure ou une confirmation.

### Exemples

* “La réunion a eu lieu mardi.”
* “Huit personnes étaient présentes.”
* “Le rapport date de 2021.”
* “Le service n’est pas ouvert le soir.”

### Erreur fréquente

Confondre un fait avec une conclusion.

Mauvais exemple :

> “Le service ne fonctionne pas.”

Meilleure formulation :

> “Le service est ouvert de 9 h à 16 h. Plusieurs personnes disent ne pas pouvoir s’y rendre pendant ces heures.”

## 05.3.3 Hypothèse

### À expliquer

Une hypothèse est une possibilité. Elle peut être utile, mais elle ne doit pas être traitée comme une vérité.

### Exemples

* “Les horaires pourraient expliquer la faible participation.”
* “Le manque de transport pourrait être un obstacle.”
* “Certaines personnes ne connaissent peut-être pas le service.”

### Erreur fréquente

Transformer une hypothèse plausible en conclusion définitive.

## 05.3.4 Interprétation

### À expliquer

Une interprétation est le sens que l’on donne à une situation. Elle dépend souvent du contexte, de l’expérience, de la position sociale, de la mémoire, de la relation et des valeurs.

### Exemples

* “Cette absence peut être comprise comme un signe de méfiance.”
* “Ce silence peut indiquer une gêne, mais il peut aussi signifier autre chose.”
* “Cette décision institutionnelle peut être perçue comme une exclusion.”

### Erreur fréquente

Croire qu’une interprétation forte est automatiquement vraie.

## 05.3.5 Décision

### À expliquer

Une décision est une orientation choisie après examen. Elle doit venir après l’écoute, l’inventaire, la clarification et la comparaison.

### Exemples

* “Nous allons consulter les jeunes avant de modifier l’activité.”
* “Nous allons reporter l’action jusqu’à validation.”
* “Nous allons commencer par un projet pilote.”

### Erreur fréquente

Décider avant d’avoir distingué les faits, les hypothèses et les interprétations.

## 05.3.6 Incertitude

### À expliquer

L’incertitude n’est pas un échec. Elle est une partie normale de la compréhension.

Nommer l’incertitude permet :

* d’éviter les conclusions abusives ;
* de préparer les vérifications ;
* de protéger les personnes ;
* de garder la démarche révisable.

### Phrase à intégrer

> Une bonne compréhension ne supprime pas toutes les incertitudes. Elle les rend visibles.

# 05.4 Transformer

## 05.4.1 Opération centrale

Ce chapitre enseigne une transformation précise :

```text
notes brutes
→ énoncés
→ classement
→ questions à vérifier
→ carte de compréhension
```

Cette logique rejoint le principe de transformation contrôlée des flows kOA : une contribution ne devient pas automatiquement connaissance ; chaque passage demande une structure, un seuil, une trace ou une interface. 

## 05.4.2 Étapes de transformation

### Étape 1 — Extraire les énoncés

À partir des notes, isoler les phrases importantes.

Exemples :

* “Les familles ne viennent plus aux rencontres.”
* “Les horaires sont difficiles.”
* “Les jeunes ne se sentent pas concernés.”
* “Le rapport de 2021 proposait déjà une solution.”

### Étape 2 — Classer chaque énoncé

Pour chaque énoncé, demander :

* est-ce un fait ?
* est-ce une hypothèse ?
* est-ce une interprétation ?
* est-ce déjà une décision ?
* est-ce une incertitude ?

### Étape 3 — Ajouter les vérifications nécessaires

Pour chaque hypothèse ou interprétation, demander :

* qui pourrait confirmer ?
* quel document pourrait aider ?
* quelle personne devrait être consultée ?
* qu’est-ce qui ne doit pas être demandé ou partagé ?
* quelle limite doit être respectée ?

### Étape 4 — Produire une carte de compréhension

La carte doit montrer :

* ce qui est vérifié ;
* ce qui est probable ;
* ce qui est interprété ;
* ce qui reste ouvert ;
* ce qui doit être validé avant de choisir.

# 05.6 Erreurs fréquentes

## Erreur 1 — Confondre observation et interprétation

Observation :

> “Trois personnes ont quitté la réunion avant la fin.”

Interprétation :

> “Elles étaient contre le projet.”

Correction :

> “Trois personnes ont quitté la réunion avant la fin. La raison de leur départ doit être vérifiée.”

## Erreur 2 — Confondre témoignage et fait général

Témoignage :

> “Je ne me sens pas accueilli dans ce service.”

Mauvaise généralisation :

> “Le service n’accueille personne correctement.”

Correction :

> “Une personne rapporte ne pas se sentir accueillie. Il faut comprendre ce qui produit cette expérience et vérifier si d’autres personnes vivent une situation semblable.”

## Erreur 3 — Confondre hypothèse et solution

Hypothèse :

> “Le manque de transport pourrait expliquer la faible participation.”

Solution trop rapide :

> “Il faut organiser un transport collectif.”

Correction :

> “Le transport est une piste à vérifier avant de décider.”

## Erreur 4 — Confondre silence et accord

Mauvaise lecture :

> “Personne n’a protesté, donc tout le monde est d’accord.”

Correction :

> “Personne n’a exprimé de désaccord. Les raisons du silence restent inconnues.”

## Erreur 5 — Confondre urgence et certitude

Mauvaise lecture :

> “C’est urgent, donc nous savons quoi faire.”

Correction :

> “L’urgence peut justifier une action rapide, mais elle ne transforme pas une hypothèse en certitude.”

# 05.7 Points de vigilance

## 05.7.1 Ne pas forcer le sens

Certaines paroles ou situations restent ambiguës.
Il faut accepter cette ambiguïté au lieu de la combler artificiellement.

## 05.7.2 Ne pas effacer les désaccords

Deux personnes peuvent donner des interprétations différentes d’un même fait.
Le désaccord doit être noté, pas supprimé.

## 05.7.3 Ne pas rendre public ce qui doit rester situé

Une information peut être utile à la compréhension sans être publiable ou réutilisable.

## 05.7.4 Garder la trace des limites

Chaque carte de compréhension devrait conserver :

* ce qui est connu ;
* ce qui est incertain ;
* ce qui est sensible ;
* ce qui doit être validé ;
* ce qui ne doit pas être partagé.

# 1. Situer

## 1.1 Rôle de ce chapitre

Ce chapitre ferme la Partie 1.

1. commencer par ce qui existe déjà ;
2. écouter avec attention ;

La Partie 1 ne sert pas encore à choisir une solution.

L’étudiant a appris à :

* reconnaître les ressources présentes ;
* écouter sans conclure trop vite ;
* observer les paroles, gestes, silences et contextes ;



# 2. Distinguer

## 2.1 Les distinctions à vérifier

Cette section sert de contrôle de qualité.

L’étudiant doit vérifier qu’il distingue bien :

| À distinguer                                       | Pourquoi c’est important                                   |
| -------------------------------------------------- | ---------------------------------------------------------- |
| Ressource / problème                               | Ne pas réduire la situation à ses manques                  |
| Écoute / extraction                                | Ne pas utiliser la parole des autres comme simple matériau |
| Fait / hypothèse                                   | Ne pas présenter une supposition comme une certitude       |
| Hypothèse / interprétation                         | Ne pas confondre possibilité et lecture personnelle        |
| Interprétation / décision                          | Ne pas décider avant d’avoir comparé les options           |
| Silence / consentement                             | Ne pas traiter l’absence de refus comme une permission     |
| Document disponible / information utilisable       | Ne pas réutiliser sans contexte ni autorisation            |
| Compréhension partielle / compréhension suffisante | Savoir quand continuer à vérifier                          |

## 2.2 Questions de vérification

L’étudiant répond brièvement :

* Ai-je commencé par les ressources ou seulement par les problèmes ?
* Ai-je écouté pour comprendre ou pour obtenir de l’information ?
* Quels faits sont réellement vérifiables ?
* Quelles hypothèses doivent encore être confirmées ?
* Quelles interprétations pourraient être contestées ?
* Quelles personnes ou voix sont absentes ?
* Qu’est-ce qui ne doit pas être partagé sans permission ?
* Qu’est-ce que je ne comprends pas encore ?

## 2.3 Erreurs fréquentes à éviter

* croire que l’inventaire des ressources est déjà une solution ;
* transformer une parole entendue en vérité générale ;
* utiliser un silence comme preuve d’accord ;
* ignorer les absences dans les notes ;
* oublier les limites de partage ;
* effacer l’incertitude pour rendre le travail plus propre ;
* passer trop vite de “je crois comprendre” à “il faut faire”.

````markdown
# 07. Ne pas courir vers la première solution

## Fonction UCKK dominante

**Distinguer → Transformer**

## Intention du chapitre

Ce chapitre apprend à reconnaître le réflexe de solution rapide.

Dans une situation difficile, il est normal de vouloir agir vite. Mais agir vite n’est pas toujours agir bien. Une première solution peut rassurer, donner l’impression d’avancer, ou répondre à une pression extérieure, tout en cachant des risques, des personnes oubliées ou des options plus responsables.

Le chapitre ne dit pas qu’il faut toujours ralentir. Il apprend plutôt à distinguer :

- quand il faut agir vite ;
- quand il faut prendre le temps d’explorer ;
- quand une solution évidente doit être questionnée ;
- quand ne pas agir tout de suite est une position responsable.

## Objectif d’apprentissage

À la fin du chapitre, l’étudiant doit pouvoir :

- reconnaître son premier réflexe de solution ;
- expliquer pourquoi cette solution semble évidente ;
- identifier ce qu’elle risque de cacher ;
- distinguer urgence réelle et urgence ressentie ;
- nommer les personnes à consulter avant de choisir ;
- suspendre temporairement le choix pour ouvrir le champ des options.

## Place dans la Partie 2

La Partie 1 a produit une compréhension prudente : ressources, observations, faits, hypothèses, interprétations et questions ouvertes.

La Partie 2 commence ici : avant d’inventorier plusieurs solutions, il faut d’abord empêcher la première solution de devenir automatiquement la décision.

Phrase de transition :

> Comprendre une situation ne donne pas encore le droit de choisir la première réponse disponible.

---

## 1. Situer

### 1.1 Le réflexe de solution rapide

Présenter une situation typique :

Une personne ou un groupe comprend mieux un problème et veut immédiatement passer à l’action. Ce mouvement peut être utile, mais il peut aussi venir de l’inconfort, de la pression, de la peur de paraître inactif ou de l’habitude.

Expliquer que le réflexe de solution rapide peut venir de plusieurs causes :

- le problème semble évident ;
- une solution familière existe déjà ;
- une personne influente propose rapidement une réponse ;
- le groupe veut réduire l’inconfort ;
- le temps semble manquer ;
- on veut montrer qu’on est efficace ;
- on confond action visible et action utile ;
- on veut éviter un désaccord plus profond.

### 1.2 Pourquoi ce réflexe est dangereux

Choisir trop vite peut faire manquer :

- une solution plus simple ;
- une ressource déjà disponible ;
- une personne à consulter ;
- un risque important ;
- une conséquence non prévue ;
- une option moins coûteuse ;
- une solution plus respectueuse ;
- une solution temporaire utile ;
- une meilleure option à moyen terme.

### 1.3 Lien avec les références

La délibération démocratique rappelle qu’une décision responsable doit prendre le temps d’examiner des raisons, de reconnaître les désaccords et de rendre les choix explicables. Dryzek, Fishkin et Fung soutiennent directement cette partie du cours : délibération, jugement informé, participation utile et décision reliée à la capacité d’agir. :contentReference[oaicite:1]{index=1}

### Phrase de section

> Le premier réflexe peut contenir une intuition utile, mais il ne doit pas devenir automatiquement la décision.

---

## 2. Distinguer

### 2.1 Action rapide et action utile

Distinguer :

| Action rapide | Action utile |
|---|---|
| Répond vite à l’inconfort | Répond à la situation réelle |
| Peut donner une impression d’efficacité | Produit un effet pertinent |
| Peut ignorer des personnes concernées | Tient compte des personnes concernées |
| Peut fermer le débat | Ouvre une décision plus claire |
| Peut déplacer le problème | Cherche à réduire les effets négatifs |

Phrase clé :

> Une action rapide peut être utile, mais sa rapidité ne prouve pas sa qualité.

---

### 2.2 Urgence réelle et urgence ressentie

Introduire une distinction essentielle.

| Type d’urgence | Description | Réponse appropriée |
|---|---|---|
| Urgence réelle | Un dommage important peut arriver bientôt | Agir vite, avec protection minimale |
| Urgence organisationnelle | Une date, une obligation ou une contrainte externe approche | Décider un premier pas limité |
| Urgence émotionnelle | Le malaise pousse à conclure vite | Ralentir, vérifier, consulter |
| Urgence politique | Une pression pousse à montrer une réponse | Documenter les limites et éviter l’effet d’annonce |

Cette distinction prépare le chapitre 10 sur le choix sous contrainte de temps.

---

### 2.3 Solution familière et solution responsable

Une solution familière est une solution qu’on connaît déjà.  
Une solution responsable est une solution qui tient compte :

- du contexte ;
- des ressources ;
- des risques ;
- des personnes concernées ;
- des effets possibles ;
- des limites de ce qu’on sait ;
- des autorisations nécessaires.

Phrase clé :

> Une solution connue n’est pas nécessairement une solution adaptée.

---

### 2.4 Ne pas agir tout de suite et rester passif

Distinguer :

| Ne pas agir tout de suite | Rester passif |
|---|---|
| Décision temporaire et justifiée | Absence de décision |
| Sert à vérifier, consulter ou protéger | Évite le problème |
| Peut réduire les dommages | Peut laisser le problème empirer |
| Prépare une meilleure action | Repousse sans méthode |

Phrase clé :

> Reporter une action peut être responsable si le report sert à vérifier, consulter ou réduire les risques.

## 3. Transformer

### 3.1 Transformation centrale du chapitre

```text
````

Ce chapitre transforme une impulsion en méthode.

Il ne bloque pas l’action.
Il crée un seuil avant l’action.

### 3.2 Le seuil de pause

Avant de retenir une solution, l’étudiant doit passer par cinq questions :

1. Pourquoi cette solution me vient-elle en premier ?
2. Quelle ressource déjà présente pourrait modifier cette solution ?
3. Qui n’a pas encore été consulté ?
4. Quel risque cette solution pourrait-elle cacher ?
5. Qu’est-ce qui arriverait si on attendait un peu avant d’agir ?

### 3.3 Mini-protocole de ralentissement

```text
1. Nommer la première solution.
2. Identifier pourquoi elle semble évidente.
3. Nommer ce qu’elle pourrait cacher.
4. Identifier les personnes à consulter.
5. Proposer au moins deux autres options.
6. Décider si l’on peut explorer davantage ou s’il faut agir vite.
```

Cette transformation correspond à un invariant UCKK : ne pas confondre une compréhension avec une décision, ni une décision avec une action. Le tronc commun UCKK insiste déjà sur la distinction entre fait, hypothèse, interprétation, récit et décision, ainsi que sur la délibération collective structurée.

* Refuser de considérer l’option de ne pas agir tout de suite.
* Présenter un choix comme évident alors qu’il reste contestable.

````markdown
## 8.1 Situer — Pourquoi inventorier les solutions ?

### Idée centrale

Avant de choisir une solution, il faut d’abord ouvrir le champ des possibles.

Un choix responsable ne commence pas par :

> Quelle est la meilleure solution ?

Il commence par :

> Quelles solutions existent réellement ?

### Pourquoi c’est important

Quand on passe trop vite de la compréhension à la solution, on risque de :

- choisir l’option la plus évidente ;
- choisir l’option déjà connue ;
- choisir l’option qui rassure le plus ;
- choisir l’option portée par la personne la plus influente ;
- oublier une solution plus simple ;
- oublier une ressource déjà disponible ;
- ignorer une limite culturelle, relationnelle ou logistique ;
- agir avant d’avoir consulté les bonnes personnes.

### Passage pédagogique

Ce chapitre enseigne à passer de :

```text
situation comprise
→ éventail d’options
→ solutions comparables
````

et non de :

```text
situation comprise
→ première solution
→ action immédiate
```

### Phrase de transition depuis le chapitre précédent

> Maintenant que la situation est mieux comprise, il ne faut pas encore choisir. Il faut d’abord élargir les possibilités.

## 8.2 Distinguer — Les types de solutions possibles

### Idée centrale

Toutes les solutions ne jouent pas le même rôle. Certaines répondent à l’urgence. D’autres préparent le long terme. D’autres consistent à ne pas agir tout de suite.

### Typologie des solutions

#### 1. Solution immédiate

Action possible maintenant, avec les ressources déjà disponibles.

Exemples :

* clarifier une information ;
* contacter une personne ;
* ouvrir une discussion ;
* réunir un petit groupe ;
* vérifier une donnée ;
* transmettre un document utile.

#### 2. Solution temporaire

Action qui réduit un problème sans le régler entièrement.

Exemples :

* solution de dépannage ;
* arrangement provisoire ;
* mesure transitoire ;
* soutien ponctuel.

#### 3. Solution communautaire

Action portée par les personnes ou ressources déjà présentes dans le milieu.

Exemples :

* groupe d’entraide ;
* partage de compétences ;
* rencontre collective ;
* projet local ;
* mobilisation d’un réseau existant.

#### 4. Solution logistique

Action qui améliore l’organisation concrète.

Exemples :

* horaire ;
* transport ;
* lieu ;
* matériel ;
* communication ;
* coordination ;
* accès à un document ou service.

#### 5. Solution éducative

Action qui transmet une connaissance ou développe une compétence.

Exemples :

* atelier ;
* formation ;
* guide ;
* séance d’information ;
* mentorat ;
* démonstration pratique.

#### 6. Solution institutionnelle

Action qui exige une organisation, une autorité ou une procédure officielle.

Exemples :

* demande formelle ;
* modification de procédure ;
* création d’un poste ;
* entente avec une institution ;
* financement ;
* politique interne.

#### 7. Solution relationnelle

Action qui vise la confiance, la médiation ou la réparation d’un lien.

Exemples :

* conversation facilitée ;
* médiation ;
* clarification des attentes ;
* rencontre entre personnes concernées ;
* reconnaissance d’un malentendu.

#### 8. Solution préventive

Action qui réduit la probabilité que le problème revienne.

Exemples :

* documentation ;
* formation ;
* procédure ;
* signalement plus clair ;
* calendrier de suivi ;
* mécanisme de vérification.

#### 9. Solution réparatrice

Action qui cherche à reconnaître un dommage ou corriger une conséquence.

Exemples :

* excuse ;
* correction publique ;
* réparation matérielle ;
* restauration d’un lien ;
* soutien à une personne affectée ;
* modification d’une décision antérieure.

#### 10. Solution à long terme

Action plus ambitieuse, qui demande davantage de temps, de ressources ou de coordination.

Exemples :

* nouveau programme ;
* infrastructure ;
* partenariat ;
* changement de gouvernance ;
* transformation institutionnelle.

#### 11. Option de ne pas agir maintenant

Option légitime lorsque l’action immédiate risque de causer plus de tort que de bien.

Exemples :

* attendre une validation ;
* consulter une autorité concernée ;
* protéger une information ;
* éviter de rendre public un contenu sensible ;
* reporter jusqu’à obtention d’un meilleur contexte.

### Point de vigilance

Ne pas agir maintenant n’est pas nécessairement refuser d’agir. Cela peut être une décision prudente lorsque les informations, permissions ou conditions ne sont pas réunies.

## 8.3 Transformer — De la compréhension aux options

### Idée centrale

L’étudiant doit apprendre à transformer ce qu’il a compris en options concrètes.

La transformation suit ce mouvement :

```text
faits et ressources
→ besoins ou tensions
→ pistes d’action
→ options classées
→ conditions de choix
```

### Questions-guides

Pour générer des solutions, poser les questions suivantes :

#### À partir des ressources

* Qu’est-ce qui existe déjà et pourrait être mobilisé ?
* Qui possède une compétence utile ?
* Quel lieu, outil, document ou réseau peut aider ?
* Quelle ressource est sous-utilisée ?

#### À partir des besoins

* Quel besoin demande une réponse immédiate ?
* Quel besoin demande une réponse plus lente ?
* Quel besoin demande surtout de l’information ?
* Quel besoin demande une décision collective ?

#### À partir des limites

* Qu’est-ce qui ne peut pas être fait maintenant ?
* Qu’est-ce qui demande permission ?
* Qu’est-ce qui exige consultation ?
* Qu’est-ce qui serait trop risqué ?

#### À partir du temps disponible

* Que peut-on faire aujourd’hui ?
* Que peut-on faire cette semaine ?
* Que peut-on préparer pour plus tard ?
* Que faut-il reporter ?

### Méthode en trois passes

#### Première passe — Générer

Produire le plus d’options possible sans choisir.

#### Deuxième passe — Classer

Regrouper les options par type :

* immédiate ;
* temporaire ;
* communautaire ;
* logistique ;
* éducative ;
* institutionnelle ;
* relationnelle ;
* préventive ;
* réparatrice ;
* à long terme ;
* à reporter.

#### Troisième passe — Clarifier

Pour chaque option, indiquer :

* son avantage ;
* son risque ;
* les ressources nécessaires ;
* le temps requis ;
* les personnes à consulter.

### Erreur fréquente

Confondre **inventorier** et **choisir**.

À cette étape, l’objectif n’est pas encore de déterminer la meilleure solution. L’objectif est de rendre les options visibles.

## 8.7 Erreurs fréquentes

### Erreur 1 — Choisir avant d’avoir inventorié

L’étudiant écrit une seule solution et commence à la justifier.

Correction :

> Revenir à l’inventaire. Produire au moins cinq options avant de choisir.

### Erreur 2 — Confondre solution réaliste et solution familière

Une solution semble réaliste seulement parce qu’elle est déjà connue.

Correction :

> Chercher une option communautaire, relationnelle ou préventive qui n’a pas encore été considérée.

### Erreur 3 — Oublier les ressources existantes

L’étudiant propose une solution qui demande beaucoup de nouvelles ressources, sans mobiliser ce qui existe déjà.

Correction :

> Revenir au tableau des ressources.

### Erreur 4 — Oublier les risques

L’étudiant liste des avantages, mais ignore les effets négatifs possibles.

Correction :

> Ajouter une colonne “risques” avant toute comparaison.

### Erreur 5 — Oublier qu’attendre peut être responsable

L’étudiant traite le report comme un échec.

Correction :

> Ajouter une option “ne pas agir maintenant” lorsque l’action immédiate serait mal informée ou risquée.

Variante courte :

> Avant de choisir, ouvrir le champ des possibles.

Variante pédagogique :

> Une solution devient responsable quand elle a été comparée à d’autres possibilités.

````markdown
# 09.1 Situer — Pourquoi comparer ?

## Idée centrale

Comparer permet de ralentir le jugement sans bloquer la décision.

Lorsque plusieurs options existent, le risque est de choisir :

- l’option la plus visible ;
- l’option la plus populaire ;
- l’option la plus rapide ;
- l’option défendue par la personne la plus influente ;
- l’option qui ressemble le plus à ce qu’on connaît déjà.

Comparer ne sert pas à produire une vérité automatique.  
Comparer sert à rendre visibles les raisons, les risques, les désaccords et les limites de chaque option.

## Pourquoi c’est important

Une décision responsable ne devrait pas sortir directement d’une préférence immédiate.

Elle devrait passer par :

1. des critères explicites ;
2. une comparaison des options ;
3. une discussion des désaccords ;
4. une attention aux personnes absentes ;
5. une reconnaissance des limites de l’analyse.

Cette logique rejoint les objectifs du tronc commun UCKK : distinguer preuve et interprétation, participer à des décisions collectives structurées et agir publiquement avec intégrité. :contentReference[oaicite:1]{index=1}

## Phrase d’ouverture possible

> Avant de choisir, il faut rendre les options comparables. Comparer ne veut pas dire éliminer la discussion ; cela veut dire mieux voir ce que chaque option rend possible, ce qu’elle risque de produire et ce qu’elle exige.

---

# 09.2 Distinguer — Ce qu’il ne faut pas confondre

## 09.2.1 Option populaire et option responsable

Une option peut être populaire parce qu’elle est :

- simple à comprendre ;
- rassurante ;
- déjà connue ;
- portée par une personne influente ;
- plus facile à défendre publiquement.

Mais une option responsable doit aussi tenir compte :

- des impacts ;
- des ressources disponibles ;
- des personnes concernées ;
- des risques ;
- des savoirs à protéger ;
- du temps requis ;
- de la possibilité de corriger si elle échoue.

### À retenir

> Une option populaire peut être bonne, mais sa popularité ne suffit pas à la rendre responsable.

---

## 09.2.2 Score et jugement

Un tableau de comparaison peut utiliser des scores, mais le score ne doit pas remplacer le jugement.

Un score aide à :

- clarifier ;
- comparer ;
- ralentir ;
- rendre les critères visibles.

Mais il ne peut pas décider seul, parce que certains éléments exigent une discussion humaine :

- dignité ;
- confiance ;
- risque culturel ;
- refus ou limite de partage ;
- effet à long terme ;
- dommage possible ;
- incertitude majeure.

### À retenir

> Un score peut éclairer un choix. Il ne doit pas devenir le choix.

---

## 09.2.3 Désaccord et blocage

Un désaccord n’est pas nécessairement un problème.

Il peut révéler :

- un risque invisible ;
- une personne oubliée ;
- une valeur importante ;
- une information manquante ;
- une tension entre court terme et long terme ;
- un effet non prévu.

La délibération ne vise pas à effacer trop vite les désaccords. Elle vise à les rendre lisibles pour que le choix soit plus responsable.

### À retenir

> Un désaccord bien formulé peut améliorer une décision.

---

## 09.2.4 Personne absente et personne non concernée

Une personne absente n’est pas nécessairement non concernée.

Avant de comparer les options, il faut demander :

- qui serait touché par cette option ?
- qui n’est pas autour de la table ?
- qui pourrait subir les effets sans avoir participé ?
- qui devrait être consulté avant d’aller plus loin ?
- qui possède une autorité ou une responsabilité particulière sur ce sujet ?

Cette distinction est importante dans un manuel destiné à des contextes communautaires, parce que certaines options peuvent toucher des personnes, des savoirs ou des territoires qui ne sont pas représentés dans la discussion.

### À retenir

> L’absence d’une personne dans la discussion ne signifie pas son absence dans les impacts.
````

# 10. Choisir sous contrainte de temps

## Fonction UCKK dominante

**Transformer → Évaluer**

## Transformation centrale du chapitre

```text
options comparées
→ contrainte de temps clarifiée
→ type de choix identifié
```

## Objectif du chapitre

Apprendre à prendre une décision **sans se précipiter**, mais sans attendre une compréhension parfaite.

L’étudiant doit comprendre qu’une bonne décision n’est pas nécessairement définitive. Elle peut être :

* provisoire ;
* conditionnelle ;
* à valider ;
* limitée dans le temps ;
* révisable.

---

# 10.1 Situer — Pourquoi le temps change la décision

## Idée centrale

Il faut explorer assez pour éviter la précipitation, mais il n’existe jamais un temps infini pour décider.

Une décision se prend toujours dans une situation imparfaite :

* information incomplète ;
* ressources limitées ;
* pression extérieure ;
* fatigue des personnes ;
* calendrier institutionnel ;
* risque d’attendre trop longtemps ;
* risque d’agir trop vite.

## Problème pédagogique

Les étudiants peuvent tomber dans deux erreurs opposées :

| Erreur            | Description                                                                |
| ----------------- | -------------------------------------------------------------------------- |
| Décider trop vite | On choisit la première solution disponible sans avoir comparé les options. |
| Ne jamais décider | On continue à chercher de l’information pour éviter le risque du choix.    |

## Idée à développer

Le chapitre doit enseigner un équilibre :

> Assez d’exploration pour éviter la précipitation. Assez de décision pour éviter la paralysie.

## Cas filé recommandé

Dans le cas d’un dossier dormant sur l’autonomie alimentaire :

* plusieurs solutions ont été identifiées ;
* certaines demandent des validations ;
* certaines sont trop longues à mettre en place ;
* une action doit quand même être choisie pour avancer.

Question du chapitre :

> Quelle option peut être retenue maintenant, sans prétendre régler toute la situation ?

---

# 10.2 Distinguer — Les types de choix

## 10.2.1 Choix provisoire

Un choix provisoire sert à avancer sans fermer la réflexion.

### Exemple

> Organiser une première rencontre exploratoire avant de lancer un programme complet.

### À utiliser quand

* l’information est incomplète ;
* les risques sont modérés ;
* il faut avancer ;
* la décision pourra être corrigée rapidement.

---

## 10.2.2 Choix final

Un choix final engage davantage.

### Exemple

> Fermer un service, signer une entente, publier un rapport, engager un budget important.

### À utiliser seulement quand

* les informations principales sont vérifiées ;
* les personnes concernées ont été consultées ;
* les impacts ont été évalués ;
* les responsabilités sont claires ;
* les conditions de révision sont connues.

---

## 10.2.3 Choix à valider

Un choix à valider est une recommandation, pas encore une décision complète.

### Exemple

> L’équipe recommande l’option B, mais la décision doit être validée par un comité, une communauté, une direction ou une personne responsable.

### À utiliser quand

* l’étudiant ou le groupe n’a pas l’autorité finale ;
* des savoirs sensibles sont impliqués ;
* des personnes absentes doivent être consultées ;
* une autorisation est nécessaire.

---

## 10.2.4 Choix de reporter

Reporter peut être responsable.

### Exemple

> Ne pas publier un résumé parce que le contexte du dossier est incomplet.

### À utiliser quand

* le risque est trop élevé ;
* les informations sont trop incertaines ;
* une personne concernée n’a pas été consultée ;
* le temps disponible ne permet pas une décision respectueuse ;
* la décision pourrait causer un dommage difficile à corriger.

## Phrase à retenir

> Reporter une décision peut être une action responsable si les conditions minimales ne sont pas réunies.

---

# 10.3 Distinguer — Les types d’urgence

## 10.3.1 Urgence réelle

Il y a urgence réelle lorsqu’un délai peut causer un dommage concret.

Exemples :

* santé ;
* sécurité ;
* perte d’accès ;
* rupture de service ;
* opportunité qui disparaît ;
* risque immédiat pour des personnes.

---

## 10.3.2 Urgence organisationnelle

Il y a urgence organisationnelle lorsqu’un calendrier impose une décision.

Exemples :

* dépôt de rapport ;
* réunion ;
* budget ;
* échéance administrative ;
* disponibilité d’une salle ;
* date limite de financement.

---

## 10.3.3 Urgence émotionnelle

Il y a urgence émotionnelle lorsqu’on veut décider vite pour réduire l’inconfort.

Exemples :

* malaise devant l’incertitude ;
* désir de rassurer ;
* pression d’avoir l’air efficace ;
* fatigue du groupe ;
* conflit qu’on veut faire disparaître.

---

## 10.3.4 Urgence politique

Il y a urgence politique lorsqu’une décision est poussée par des rapports de pouvoir.

Exemples :

* pression d’une institution ;
* visibilité médiatique ;
* enjeu de réputation ;
* besoin de montrer un résultat ;
* influence d’un acteur dominant.

## Tableau de clarification

| Type d’urgence    | Ce qui la crée   | Risque principal              | Comment ralentir sans bloquer            |
| ----------------- | ---------------- | ----------------------------- | ---------------------------------------- |
| Réelle            | Dommage possible | Attendre trop longtemps       | Décider un geste minimal                 |
| Organisationnelle | Calendrier       | Confondre délai et importance | Décider ce qui est nécessaire maintenant |
| Émotionnelle      | Inconfort        | Choisir pour se rassurer      | Nommer l’émotion avant de décider        |
| Politique         | Pression externe | Céder au plus influent        | Rendre les critères visibles             |

---

Questions :

* Qu’est-ce qui pourrait changer cette décision ?
* Quelle information manque encore ?
* Qui doit pouvoir contester ou corriger ?
* Quand faut-il revoir la décision ?
* Quels signes indiqueraient qu’il faut ralentir ou arrêter ?

* elle explique pourquoi certaines options sont écartées ;
* elle tient compte du temps disponible ;
* elle indique ce qui doit être validé ;
* elle prévoit une révision ;
* elle permet un prochain geste concret.

# 10.8 Erreurs fréquentes

## Erreur 1 — Confondre urgence et pression

Une institution peut exiger une réponse rapide, mais cela ne signifie pas que tout doit être décidé définitivement.

## Erreur 2 — Choisir pour se rassurer

Une décision peut réduire l’inconfort sans être responsable.

## Erreur 3 — Faire passer un choix provisoire pour un choix final

Cela crée de la confusion et peut fermer trop tôt la révision.

## Erreur 4 — Oublier les personnes absentes

Une décision peut sembler claire seulement parce que certaines voix n’ont pas été entendues.

## Erreur 5 — Ne pas documenter les limites

Une décision sans limites écrites peut être réutilisée plus tard comme si elle était plus solide qu’elle ne l’était.

---

# 10.9 Retenir

## Phrase clé

> Une bonne décision est assez claire pour agir et assez humble pour être révisée.

## Autres formulations possibles

> Choisir, ce n’est pas prétendre que tout est réglé. C’est décider du meilleur prochain pas.

> Une décision responsable nomme ses raisons, ses limites et ses conditions de révision.

> Le temps disponible influence la décision, mais il ne doit pas effacer la prudence.

* une action prématurée.

# 2. Distinguer — Ne pas confondre option, décision et action

## 2.1 Distinctions principales

Inclure un tableau de clarification :

| À distinguer | Définition                               | Question à poser                                  |
| ------------ | ---------------------------------------- | ------------------------------------------------- |
| Option       | Possibilité parmi d’autres               | Qu’est-ce qu’on pourrait faire ?                  |
| Décision     | Option retenue avec justification        | Pourquoi celle-ci maintenant ?                    |
| Action       | Geste concret réalisé                    | Qui fait quoi, quand et avec quelles ressources ? |
| Désaccord    | Différence de lecture ou de priorité     | Qu’est-ce que ce désaccord révèle ?               |
| Blocage      | Empêchement réel à avancer               | Qu’est-ce qui empêche le passage à l’action ?     |
| Urgence      | Limite réelle de temps                   | Qu’est-ce qui doit être décidé maintenant ?       |
| Pression     | Force sociale, politique ou émotionnelle | Est-ce vraiment urgent ou seulement pressant ?    |

## 2.2 Option et décision

Expliquer :

Une option est une possibilité.
Une décision est une option retenue, avec des raisons.

Formulation :

> Une option peut être intéressante sans être retenue. Une décision doit expliquer pourquoi une option est choisie maintenant plutôt qu’une autre.

## 2.3 Désaccord et blocage

Expliquer :

Un désaccord n’est pas nécessairement un problème. Il peut révéler :

* un risque invisible ;
* une valeur importante ;
* une personne oubliée ;
* une contrainte réelle ;
* une meilleure option ;
* une limite de temps ;
* une information manquante.

Un blocage, lui, empêche réellement d’avancer.

## 2.4 Urgence et pression

Expliquer :

L’urgence vient d’une contrainte réelle.
La pression vient d’une attente, d’une émotion, d’un intérêt ou d’un contexte politique.

Questions à inclure :

* Que se passe-t-il si on ne décide pas maintenant ?
* Qui dit que c’est urgent ?
* Quelle conséquence réelle est associée au délai ?
* Est-ce une urgence pratique, relationnelle, institutionnelle ou émotionnelle ?

## 2.5 Choix et action

Expliquer :

Choisir n’est pas encore agir.
La Partie 3 commencera précisément là : transformer le choix en action, responsabilités et impacts.

Phrase à inclure :

> Le choix indique une direction. L’action engage des personnes, des ressources et des conséquences.

# 3. Transformer — De l’inventaire des solutions au choix justifié

Présenter la transformation :


## 3.2 Étapes de transformation

L’étudiant doit passer par cinq opérations.

### Étape 1 — Relire l’inventaire des solutions

Vérifier :

* Y a-t-il au moins trois options ?
* Les options sont-elles vraiment différentes ?

* ce qui manque ;
* ce qui doit être validé ;

Ne pas présenter le choix comme une vérité finale.

Formulation :

> Le choix justifié est une orientation provisoire et responsable. Il permet d’avancer sans prétendre avoir tout compris.

````markdown
## 12.1 Situer — Une décision n’est pas encore une action

### Idée centrale

Une décision devient réelle seulement lorsqu’elle est traduite en responsabilités, étapes, ressources, échéances et suivis.

Une décision peut être claire, argumentée et pertinente, mais rester sans effet si personne ne sait :

- quoi faire ;
- par où commencer ;
- qui est responsable ;
- avec quelles ressources ;
- à quel moment ;
- comment suivre ce qui se passe.

### À développer

Expliquer que beaucoup de démarches s’arrêtent au moment de la décision :

> “Nous avons choisi une option.”

Mais ce choix ne devient utile que lorsqu’il se transforme en action possible :

> “Voici le premier geste, la personne responsable, les ressources nécessaires, l’échéance et le suivi.”

### Point de vigilance

Le but n’est pas encore de faire un grand plan complet.  
Le but est de définir un **premier geste responsable**.

### Phrase à introduire

> Une décision sans responsabilité reste une intention.

---

## 12.2 Distinguer — Décision, intention, action, responsabilité

### Idée centrale

Avant d’agir, il faut distinguer plusieurs choses que l’on confond souvent.

### Distinctions à enseigner

| Distinction | Explication |
|---|---|
| Décision / action | Une décision choisit une direction ; une action pose un geste concret. |
| Intention / responsabilité | Une intention exprime ce qu’on veut faire ; une responsabilité nomme qui doit faire quoi. |
| Plan ambitieux / premier geste réaliste | Un grand plan peut inspirer ; un premier geste permet de commencer. |
| Action pour les personnes / action avec les personnes | Agir “pour” peut devenir paternaliste ; agir “avec” implique consultation, validation et participation. |
| Responsable / coupable | Être responsable ne veut pas dire porter la faute ; cela veut dire porter un rôle clair. |
| Suivi / contrôle | Le suivi observe et apprend ; le contrôle peut imposer ou surveiller de manière excessive. |

### Point de vigilance

Il faut éviter deux erreurs opposées :

1. **L’action trop rapide** : agir sans responsabilité claire.
2. **Le plan trop lourd** : tellement détaillé qu’aucun premier geste ne se produit.
````

### Étape 1 — Reprendre le choix justifié


### Étape 2 — Définir le seuil d’action

Le seuil d’action répond à la question :

> Qu’est-ce qui doit être vrai, prêt ou validé pour que l’on puisse poser le premier geste ?

Exemples de seuils :

* une personne responsable est nommée ;
* une permission est obtenue ;
* une ressource est disponible ;
* une information essentielle est vérifiée ;
* une personne concernée a été consultée ;
* un risque majeur est reconnu ;
* le premier geste est limité et réversible.

### Étape 3 — Nommer les responsabilités visibles

Une responsabilité visible précise :

* qui agit ;
* qui valide ;
* qui soutient ;
* qui doit être informé ;
* qui peut signaler un problème ;
* qui garde la trace.

### Étape 4 — Définir le premier geste réaliste

Le premier geste doit être :

* concret ;
* limité ;
* faisable ;
* proportionné ;
* situé ;
* suivi ;
* révisable.

### Étape 5 — Prévoir un suivi minimal

Le suivi minimal répond à trois questions :

* Comment saura-t-on que l’action a eu lieu ?
* Qui observera ce qui se passe ?
* Quand fera-t-on un retour ?

> Le premier geste responsable n’est pas forcément le plus grand geste. C’est celui qui peut être posé clairement, suivi correctement et corrigé si nécessaire.

# 13. Prévoir les multiples impacts

## Fonction UCKK dominante

**Évaluer**

## Transformation du chapitre

```text
action prévue
→ effets possibles
→ personnes / lieux / relations affectés
→ risques
→ protections
→ conditions de suivi
→ décision d’agir, modifier ou reporter
```

## Objectif du chapitre

À la fin du chapitre, l’étudiant doit être capable de :

* reconnaître qu’une bonne intention ne garantit pas un bon impact ;
* distinguer plusieurs types d’impacts ;
* prévoir les effets directs, indirects et invisibles d’une action ;
* identifier qui ou quoi pourrait être affecté ;
* distinguer risques acceptables et inacceptables ;
* proposer des mesures de réduction des risques ;
* décider s’il faut agir, modifier l’action, consulter davantage ou reporter.

---

# 1. Situer

## 1.1 Idée centrale

Une action responsable n’est pas seulement une action réalisée avec une bonne intention.

Elle doit aussi prévoir :

* ce qu’elle peut produire ;
* qui elle peut affecter ;
* ce qu’elle peut déplacer ;
* ce qu’elle peut révéler ;
* ce qu’elle peut abîmer ;
* ce qu’elle peut renforcer ;
* ce qu’elle peut rendre possible.

Phrase d’ouverture possible :

> Avant d’agir, il faut regarder plus loin que le résultat espéré.

## 1.2 Pourquoi prévoir les impacts

Expliquer qu’une action peut réussir sur un plan et échouer sur un autre.

Exemples :

* une action efficace peut briser une relation de confiance ;
* une solution rapide peut créer une dépendance ;
* une information utile peut exposer une personne ;
* une amélioration logistique peut déplacer la charge vers quelqu’un d’autre ;
* une intervention visible peut rendre invisibles des personnes plus discrètes ;
* une solution extérieure peut affaiblir une capacité locale.

## 1.3 Place du chapitre dans le guide

Ce chapitre vient après :

```text
12. Transformer une décision en action
```

Le chapitre 12 transforme le choix en plan d’action.
Le chapitre 13 vérifie ce que ce plan pourrait produire.

Il prépare le chapitre suivant :

```text
14. Suivre, corriger, ajuster
```

Prévoir les impacts avant l’action permet ensuite de mieux observer les effets réels après l’action.

## 1.4 Exemple filé

Cas filé :

> Une organisation veut relancer un projet d’autonomie alimentaire à partir d’anciens rapports et consultations.

Action prévue :

> Organiser un atelier communautaire pour identifier les prochaines étapes.

Impacts possibles :

* positif : relancer l’intérêt ;
* positif : identifier des ressources oubliées ;
* négatif : fatiguer des personnes déjà consultées plusieurs fois ;
* négatif : créer des attentes sans capacité réelle de suivi ;
* invisible : raviver une frustration liée à des consultations passées sans action ;
* informationnel : faire circuler des documents qui n’étaient pas destinés à être publics.

---

# 2. Distinguer

## 2.1 Distinction principale

Distinguer :

```text
intention ≠ impact
action ≠ résultat
résultat visible ≠ effet complet
impact positif ≠ absence de risque
consultation ≠ consentement
information utile ≠ information partageable
risque faible ≠ risque acceptable
```

## 2.2 Définition d’un impact

Définition simple :

> Un impact est un effet produit par une action sur une personne, une relation, un groupe, un lieu, une institution, une ressource, une information ou une situation.

Ajouter :

> Un impact peut être prévu ou imprévu, visible ou invisible, positif ou négatif, immédiat ou différé.

## 2.3 Types d’impacts à distinguer

### 1. Impacts directs

Effets immédiats et visibles de l’action.

Exemples :

* une rencontre a lieu ;
* un document est produit ;
* une personne est contactée ;
* une ressource est mobilisée ;
* une décision est annoncée.

Question-guide :

> Qu’est-ce que l’action produit directement ?

---

### 2. Impacts indirects

Effets secondaires ou conséquences en chaîne.

Exemples :

* une personne doit assumer plus de travail ;
* une institution est sollicitée ;
* un conflit ancien réapparaît ;
* une attente est créée ;
* une information circule plus largement que prévu.

Question-guide :

> Qu’est-ce que cette action risque de provoquer ensuite ?

---

### 3. Impacts invisibles

Effets difficiles à mesurer immédiatement.

Exemples :

* perte de confiance ;
* fatigue ;
* sentiment d’exclusion ;
* gêne ;
* méfiance ;
* impression d’être utilisé ;
* peur de parler ;
* renforcement d’une hiérarchie implicite.

Question-guide :

> Qu’est-ce qui pourrait être affecté sans apparaître dans les résultats visibles ?

---

### 4. Impacts positifs

Effets souhaitables.

Exemples :

* clarifier une situation ;
* mobiliser des ressources ;
* reconnaître des compétences ;
* ouvrir une discussion ;
* réduire une charge ;
* réactiver un dossier utile ;
* renforcer une relation.

Question-guide :

> Qu’est-ce que cette action pourrait améliorer ?

---

### 5. Impacts négatifs

Effets dommageables ou problématiques.

Exemples :

* exposer une information sensible ;
* créer de fausses attentes ;
* déplacer un problème ;
* épuiser des personnes ;
* renforcer une injustice ;
* produire une décision trop rapide ;
* fragiliser une relation.

Question-guide :

> Qu’est-ce que cette action pourrait abîmer ou compliquer ?

---

### 6. Impacts relationnels

Effets sur les relations entre personnes, groupes ou institutions.

Exemples :

* confiance renforcée ;
* confiance diminuée ;
* tensions ;
* alliances ;
* malentendus ;
* sentiment de reconnaissance ;
* sentiment d’instrumentalisation.

Question-guide :

> Comment cette action peut-elle modifier les relations ?

---

### 7. Impacts culturels

Effets sur les pratiques, les récits, les manières de faire, les langues ou les protocoles.

Exemples :

* respecter ou contourner une manière locale de faire ;
* rendre visible une pratique qui devait rester située ;
* simplifier excessivement un savoir ;
* imposer un vocabulaire extérieur ;
* négliger une forme de transmission.

Question-guide :

> Quelles pratiques, significations ou limites culturelles peuvent être touchées ?

---

### 8. Impacts territoriaux

Effets sur les lieux, les usages du territoire, les saisons, les déplacements ou les relations aux vivants.

Exemples :

* modifier l’usage d’un lieu ;
* intensifier des déplacements ;
* négliger une contrainte saisonnière ;
* affecter une pratique située ;
* traiter un lieu comme simple ressource logistique.

Question-guide :

> Quels lieux, usages ou relations territoriales pourraient être affectés ?

Cette attention rejoint les références contemporaines qui insistent sur les relations aux lieux, aux vivants, aux pratiques situées et aux responsabilités méthodologiques. 

---

### 9. Impacts informationnels

Effets liés aux documents, données, archives, paroles ou informations.

Exemples :

* diffusion non prévue ;
* perte de contexte ;
* mauvaise interprétation ;
* réutilisation sans permission ;
* exposition d’une personne ;
* transformation d’une parole située en information générale ;
* circulation d’un document sensible.

Question-guide :

> Quelle information pourrait circuler, être mal comprise ou être réutilisée sans autorisation ?

Les références OCAP® et CARE sont particulièrement importantes ici : elles rappellent que l’accès, le contrôle, l’autorité et la responsabilité doivent accompagner toute réutilisation d’informations ou de savoirs. 

---

### 10. Risques acceptables et inacceptables

Distinguer :

| Type de risque      | Description                                                                        |
| ------------------- | ---------------------------------------------------------------------------------- |
| Risque acceptable   | Risque limité, compris, réversible ou réductible                                   |
| Risque à réduire    | Risque réel, mais modifiable par une précaution                                    |
| Risque à valider    | Risque qui exige consultation ou autorisation                                      |
| Risque inacceptable | Risque trop grave, non consenti, non réversible ou contraire aux limites du projet |

Question-guide :

> Ce risque peut-il être réduit, accepté, validé ou doit-il arrêter l’action ?

---

# 3. Transformer

## 3.1 Opération centrale du chapitre

L’étudiant apprend à transformer un plan d’action en carte des impacts.

```text
action prévue
→ effets possibles
→ personnes / lieux / ressources affectés
→ risques
→ protections
→ décision d’ajuster ou d’agir
```

## 3.2 Étapes de transformation

### Étape 1 — Nommer l’action prévue

Écrire clairement :

> L’action prévue est : ______

Exemple :

> Organiser une rencontre pour relancer un projet d’autonomie alimentaire.

---

### Étape 2 — Identifier le résultat espéré

Demander :

* qu’est-ce que l’action cherche à produire ?
* quel changement est attendu ?
* quel problème veut-elle réduire ?
* quelle ressource veut-elle activer ?

---

### Étape 3 — Nommer les personnes ou groupes affectés

Inclure :

* personnes directement impliquées ;
* personnes indirectement touchées ;
* personnes absentes de la décision ;
* personnes responsables du suivi ;
* institutions concernées ;
* générations ou groupes futurs si pertinent.

---

### Étape 4 — Lister les impacts positifs possibles

Demander :

* qu’est-ce qui pourrait s’améliorer ?
* quelle ressource pourrait être activée ?
* quelle relation pourrait être renforcée ?
* quel apprentissage pourrait être produit ?
* quelle action future pourrait devenir possible ?

---

### Étape 5 — Lister les impacts négatifs possibles

Demander :

* qu’est-ce qui pourrait être fragilisé ?
* qui pourrait porter une charge supplémentaire ?
* quelle information pourrait être exposée ?
* quelle attente pourrait être créée ?
* quel conflit pourrait être ravivé ?
* quel problème pourrait être déplacé ailleurs ?

---

### Étape 6 — Identifier les impacts invisibles

Demander :

* qui pourrait se taire ?
* qui pourrait se sentir oublié ?
* qui pourrait être fatigué par une consultation de plus ?
* quelle confiance pourrait être perdue ?
* quelle relation pourrait être modifiée sans qu’on le voie immédiatement ?

---

### Étape 7 — Évaluer les risques

Pour chaque risque, demander :

* est-il grave ?
* est-il probable ?
* est-il réversible ?
* est-il consenti ?
* peut-il être réduit ?
* qui doit être consulté ?
* faut-il reporter l’action ?

---

### Étape 8 — Définir les protections

Les protections peuvent inclure :

* anonymiser ;
* consulter avant de diffuser ;
* limiter l’accès à un document ;
* réduire l’ampleur de l’action ;
* commencer par un petit test ;
* nommer une personne responsable du suivi ;
* prévoir un moment de correction ;
* reporter si les conditions ne sont pas réunies.

---

### Étape 9 — Décider : agir, modifier, consulter ou reporter

Quatre décisions possibles :

| Décision  | Quand l’utiliser                                                     |
| --------- | -------------------------------------------------------------------- |
| Agir      | Les impacts sont compris et les risques sont acceptables             |
| Modifier  | L’action est utile, mais doit être ajustée                           |
| Consulter | Une autorité, personne ou groupe doit être impliqué avant d’agir     |
| Reporter  | Les risques, incertitudes ou permissions rendent l’action prématurée |

## 3.3 Erreurs fréquentes

* croire qu’une bonne intention suffit ;
* ne regarder que le résultat espéré ;
* oublier les personnes indirectement affectées ;
* ignorer les impacts invisibles ;
* traiter les impacts informationnels comme secondaires ;
* oublier les effets à long terme ;
* confondre risque faible et risque acceptable ;
* agir sans condition de suivi ;
* ne pas prévoir de correction possible.

## 3.4 Point de vigilance

Formulation recommandée :

> Une action responsable n’est pas seulement une action qui vise le bien. C’est une action qui accepte d’examiner ce qu’elle peut aussi déranger, exposer, déplacer ou fragiliser.

# Chapitre 14 — Suivre, corriger, ajuster

## Fonction UCKK dominante

```text

```

## Transformation centrale du chapitre

```text
action réalisée
→ effets observés
→ écarts nommés
→ correction responsable
→ leçon retenue
→ mémoire utile
```

## Objectif du chapitre

À la fin du chapitre, l’étudiant doit être capable de :

* observer les effets réels d’une action ;
* comparer ce qui était prévu avec ce qui s’est produit ;
* distinguer imprévu, erreur, dommage et mauvaise hypothèse ;
* proposer une correction proportionnée ;
* documenter l’apprentissage sans surcollecter d’information ;
* transformer l’expérience en mémoire utile pour la suite.

---

# 14.1 Situer — Le suivi comme responsabilité après l’action

## Idée centrale

Le suivi permet à l’action de rester responsable après sa mise en œuvre.

Une action ne devient pas responsable seulement parce qu’elle a été bien planifiée. Elle doit aussi être observée après coup :

* qu’a-t-elle produit ?
* qui a été affecté ?
* qu’est-ce qui a changé ?
* qu’est-ce qui n’était pas prévu ?
* qu’est-ce qui doit être corrigé ?
* qu’est-ce qui doit être retenu ?

## Contenu à développer

Expliquer que le suivi n’est pas une formalité administrative. Il permet de vérifier si l’action a réellement produit les effets attendus ou si elle a créé des effets inattendus.

Le chapitre doit insister sur cette idée :

> Une action n’est pas terminée quand elle est faite. Elle est terminée quand ses effets ont été observés, compris et, si nécessaire, corrigés.

## Références mobilisées

* **Schön** : pratique réflexive, réflexion dans et après l’action.
* **Vanclay** : attention aux impacts sociaux intentionnels et non intentionnels.
* **Graham et al.** : transformation des connaissances en action, puis retour de l’action vers l’apprentissage.

Voir la bibliographie commentée pour les références complètes. 

---

# 14.2 Distinguer — Suivi et surveillance

## Idée centrale

Le suivi vise à apprendre et corriger.
La surveillance vise à contrôler.

Le manuel doit éviter que le suivi devienne une collecte excessive, intrusive ou punitive.

## Distinctions à enseigner

| Confusion à éviter               | Distinction à faire                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| Suivi = surveillance             | Le suivi observe les effets pour apprendre ; la surveillance contrôle les personnes  |
| Trace utile = tout documenter    | Une trace utile conserve seulement ce qui aide à comprendre, corriger ou transmettre |
| Évaluer = juger les personnes    | Évaluer consiste d’abord à comprendre les effets d’une action                        |
| Correction = faute personnelle   | Une correction peut viser une méthode, une hypothèse, une étape ou un contexte       |
| Transparence = exposition totale | Certaines informations doivent rester limitées, protégées ou anonymisées             |

## Contenu à développer

Expliquer que le suivi doit être proportionné. On ne collecte pas tout “au cas où”. On documente ce qui aide réellement à :

* comprendre l’écart ;
* réduire un risque ;
* améliorer l’action ;
* protéger les personnes ;
* transmettre une leçon utile.

## Phrase à retenir

> Suivre une action, ce n’est pas surveiller les personnes. C’est observer les effets pour mieux agir.

---

# 14.3 Distinguer — Erreur, dommage, imprévu, mauvaise hypothèse

## Idée centrale

Tous les écarts ne sont pas de même nature. Pour corriger correctement, il faut d’abord nommer le type d’écart.

## Typologie des écarts

| Type d’écart        | Définition                                | Exemple                                                         | Réponse appropriée             |
| ------------------- | ----------------------------------------- | --------------------------------------------------------------- | ------------------------------ |
| Imprévu             | Effet non anticipé, sans faute claire     | Une ressource n’était finalement pas disponible                 | Ajuster le plan                |
| Mauvaise hypothèse  | Une supposition de départ était fausse    | On croyait qu’un service était accessible, mais il ne l’est pas | Réviser la compréhension       |
| Erreur              | Une étape a été mal faite ou oubliée      | Une personne clé n’a pas été consultée                          | Corriger et documenter         |
| Dommage             | L’action a causé un effet négatif réel    | Une information sensible a circulé trop largement               | Réparer, limiter, protéger     |
| Résistance légitime | Une personne ou un groupe refuse la suite | Un groupe ne veut pas valider l’action                          | Respecter, comprendre, réviser |

## Contenu à développer

Expliquer qu’une erreur n’est pas toujours un dommage, et qu’un imprévu n’est pas toujours une erreur. Mais tous les écarts importants doivent être nommés.

## Phrase à retenir

> On corrige mieux lorsqu’on nomme précisément ce qui s’est passé.

---

# 14.4 Distinguer — Correction et perte de face

## Idée centrale

Dans beaucoup de contextes, corriger peut être perçu comme un échec, une critique ou une perte de crédibilité. Le guide doit renverser cette perception.

## Contenu à développer

Expliquer que la correction est une force méthodologique. Elle montre que la démarche reste vivante, attentive et responsable.

Corriger peut signifier :

* reconnaître une information manquante ;
* modifier une étape ;
* consulter une personne oubliée ;
* réduire un risque ;
* suspendre une action ;
* reformuler une décision ;
* protéger une information ;
* reconnaître un dommage ;
* préparer une meilleure suite.

## Distinction importante

| Mauvaise lecture de la correction  | Bonne lecture de la correction            |
| ---------------------------------- | ----------------------------------------- |
| Corriger = admettre qu’on a échoué | Corriger = protéger la suite              |
| Corriger = perdre la face          | Corriger = rendre la démarche plus fiable |
| Corriger = tout recommencer        | Corriger = ajuster ce qui doit l’être     |
| Corriger = blâmer                  | Corriger = apprendre et réparer           |

## Phrase clé

> Corriger n’est pas perdre la face. Corriger, c’est protéger la suite.

---

# 14.5 Transformer — De l’expérience à l’apprentissage

## Idée centrale

L’action produit de l’expérience. Mais l’expérience ne devient apprentissage que si elle est relue, organisée et transmise avec prudence.

## Opération à enseigner

```text
action réalisée
→ effets observés
→ écarts nommés
→ causes possibles
→ correction
→ trace
→ mémoire utile
```

## Méthode en sept étapes

1. **Observer** ce qui s’est réellement passé.
2. **Comparer** avec ce qui était prévu.
3. **Identifier l’écart** entre plan et réalité.
4. **Comprendre la cause** possible.
5. **Corriger** ce qui peut l’être.
6. **Documenter** la leçon.
7. **Réviser** le plan, la méthode ou la mémoire du projet.

## Vigilance

Ne pas transformer l’expérience en récit trop propre. Il faut garder :

* les écarts ;
* les incertitudes ;
* les limites ;
* les corrections ;
* les effets non prévus ;
* ce qui reste à vérifier.

Cette logique rejoint l’idée que la valeur d’un système vient des passages structurés : de l’action à la mémoire, puis de la mémoire à une nouvelle capacité de connaître.

# 14.7 Produire — Boucle de correction

## Boucle standard

```text
1. Observer
2. Comparer
3. Identifier l’écart
4. Comprendre la cause
5. Corriger
6. Documenter
7. Réviser
```

## Développement des étapes

### 1. Observer

Décrire ce qui s’est produit sans interpréter trop vite.

### 2. Comparer

Comparer le résultat réel avec ce qui était prévu.

### 3. Identifier l’écart

Nommer la différence entre le plan et la réalité.

### 4. Comprendre la cause

Chercher les causes possibles sans réduire trop vite à une faute personnelle.

### 5. Corriger

Proposer une correction proportionnée.

### 6. Documenter

Conserver une trace utile, limitée et respectueuse.

### 7. Réviser

Modifier le plan, la méthode, la décision ou la mémoire du projet.

## Phrase à retenir

> Une boucle de correction transforme une erreur possible en apprentissage utilisable.

## Critères de réussite

L’exercice est réussi si :

* l’écart est clairement nommé ;

* la trace conservée est utile ;
* les informations sensibles ne sont pas exposées inutilement.

# 14.9 Distinguer — Trace utile et collecte abusive

## Idée centrale

La mémoire du projet doit être utile, mais elle ne doit pas tout conserver.

## Distinction importante

| Trace utile                        | Collecte abusive                          |
| ---------------------------------- | ----------------------------------------- |
| Sert à comprendre une décision     | Accumule des détails inutiles             |
| Aide à corriger une action         | Expose des personnes sans nécessité       |
| Garde les raisons et limites       | Garde tout sans tri                       |
| Respecte les permissions           | Réutilise sans contexte                   |
| Protège les informations sensibles | Rend visible ce qui devrait rester limité |

## Questions-guides

Avant de conserver une information, demander :

* pourquoi faut-il garder cette trace ?
* qui pourrait y avoir accès ?
* qui pourrait être affecté par cette trace ?
* cette information est-elle nécessaire ?
* peut-elle être anonymisée ?
* doit-elle rester restreinte ?
* combien de temps doit-elle être conservée ?

## Référence liée

Cette prudence est cohérente avec les principes de souveraineté des données et de protection des savoirs présents dans la bibliographie commentée, notamment OCAP® et CARE.

Une mémoire utile doit aussi garder les obstacles, les écarts et les corrections.

# 15. Reconnaître les savoirs dormants

## Fonction UCKK dominante

**Mémoriser**

## Transformation centrale du chapitre

```text
trace oubliée
→ dossier identifié
→ statut clarifié
→ limites reconnues
→ potentiel d’action évalué
```

## Rôle du chapitre dans le manuel

Ce chapitre ouvre la **Partie 4 — Réactiver les savoirs dormants**.

Après avoir appris à inventorier, écouter, choisir et agir, l’étudiant doit maintenant apprendre à regarder ce qui existe déjà dans les archives, les notes, les rapports, les consultations ou les expériences passées.

Le but n’est pas de tout réutiliser.
Le but est de reconnaître ce qui peut encore servir, ce qui doit être vérifié, ce qui doit être protégé, et ce qui ne doit pas être réactivé.

Cette logique rejoint le principe UCKK selon lequel une action ne devient pas automatiquement mémoire : il faut une structure, une trace et une méthode de réutilisation prudente. 

---

# 15.1 Idée centrale du chapitre

## Message principal

Un savoir dormant est une information, une expérience, une trace ou un document qui existe déjà, mais qui n’est plus activement utilisé.

Il peut devenir une ressource pour l’action, mais seulement si son origine, son contexte, ses limites et ses permissions sont clarifiés.

## Phrase d’ouverture possible

> Beaucoup d’organisations possèdent déjà des savoirs utiles : rapports, notes, consultations, cartes, bilans, témoignages, décisions passées. Ces savoirs prennent parfois la poussière, non parce qu’ils sont inutiles, mais parce qu’ils n’ont jamais été transformés en mémoire active.

## Objectif pédagogique

À la fin du chapitre, l’étudiant doit être capable de reconnaître un dossier dormant, d’en identifier le statut, et de décider s’il peut être utilisé, vérifié, protégé ou écarté.

---

# 15.2 Situer

## 15.2.1 Pourquoi parler de savoirs dormants

Développer l’idée suivante :

Une communauté, une institution ou une équipe n’a pas toujours besoin de recommencer à zéro.

Souvent, il existe déjà :

* des rapports ;
* des notes de réunion ;
* des consultations ;
* des archives ;
* des bilans ;
* des cartes ;
* des témoignages ;
* des décisions passées ;
* des projets interrompus ;
* des diagnostics ;
* des documents produits mais non suivis.

Ces documents peuvent contenir des informations utiles, mais ils peuvent aussi être incomplets, dépassés, sensibles ou hors contexte.

## 15.2.2 Pourquoi les savoirs deviennent dormants

Un savoir peut devenir dormant pour plusieurs raisons :

* manque de temps ;
* changement de personnel ;
* absence de suivi ;
* mauvaise organisation documentaire ;
* document trop long ;
* absence de responsable ;
* perte de contexte ;
* information sensible ;
* projet interrompu ;
* consultation sans suite ;
* rapport produit pour répondre à une obligation, mais jamais transformé en action.

## 15.2.3 La différence entre archive et mémoire utile

Distinguer dès le départ :

| Terme                       | Sens                                                         |
| --------------------------- | ------------------------------------------------------------ |
| **Archive**                 | Trace conservée                                              |
| **Dossier dormant**         | Trace conservée mais peu ou pas utilisée                     |
| **Mémoire utile**           | Trace comprise, contextualisée et réutilisable avec prudence |
| **Information actionnable** | Information qui peut guider une décision ou une action       |

Phrase à intégrer :

> Une archive garde une trace. Une mémoire utile permet d’apprendre de cette trace.

## 15.2.4 Prudence de départ

Le chapitre doit établir une règle forte :

> Un document disponible n’est pas automatiquement un document utilisable.

C’est particulièrement important lorsque le dossier touche :

* des personnes ;
* des communautés ;
* des savoirs situés ;
* des données sensibles ;
* des décisions anciennes ;
* des consultations ;
* des récits ;
* des informations autochtones ou communautaires.

La bibliographie du cours souligne cette prudence à travers OCAP®, CARE, Smith, Wilson et Kovach : les savoirs et données ne doivent pas être traités comme de simples ressources libres à extraire.

# 15.3 Distinguer

## 15.3.1 Les quatre statuts du savoir dormant

Inclure le tableau principal.

| Statut               | Description                                                | Ce qu’on peut faire                                |
| -------------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| **Utilisable**       | Clair, validé, contextualisé, partageable                  | Transformer en outil, résumé, fiche ou action      |
| **À vérifier**       | Potentiellement utile, mais incomplet ou incertain         | Identifier les validations nécessaires             |
| **Sensible**         | Délicat, limité, personnel, communautaire ou restreint     | Restreindre l’accès, demander permission, protéger |
| **Non réutilisable** | Trop incertain, hors contexte, non autorisé ou trop risqué | Ne pas utiliser pour l’action                      |

## 15.3.2 Utilisable

### À expliquer

Un dossier est utilisable si :

* son origine est claire ;
* son contexte est compréhensible ;
* son contenu est encore pertinent ;
* les limites sont connues ;
* il peut être partagé ou mobilisé sans dommage ;
* les personnes concernées peuvent le reconnaître comme valable.

### Exemples

* une liste publique de ressources communautaires encore à jour ;
* un bilan validé d’une activité passée ;
* une carte logistique produite par l’équipe actuelle ;
* un rapport dont les données sont encore pertinentes.

### Erreur fréquente

Croire qu’un document bien écrit est automatiquement utilisable.

## 15.3.3 À vérifier

### À expliquer

Un dossier peut être utile, mais demander confirmation.

Il peut contenir :

* des données anciennes ;
* des informations partielles ;
* des hypothèses non validées ;
* des recommandations jamais testées ;
* des noms ou rôles qui ont changé ;
* des contraintes devenues obsolètes.

### Exemples

* un rapport de 2019 sur un besoin encore présent ;
* une note de réunion sans liste de participants ;
* une consultation dont on ne connaît pas la méthode ;
* une recommandation qui semble pertinente, mais qui n’a pas été validée.

### Erreur fréquente

Utiliser une information ancienne comme si elle était actuelle.

## 15.3.4 Sensible

### À expliquer

Un dossier sensible peut contenir une information utile, mais dont l’usage doit être limité.

Il peut toucher :

* des personnes identifiables ;
* des conflits ;
* des récits personnels ;
* des savoirs communautaires ;
* des informations territoriales ;
* des données de santé ;
* des décisions politiques ;
* des éléments partagés dans un contexte restreint.

### Exemples

* notes d’une rencontre confidentielle ;
* témoignages non anonymisés ;
* informations sur des familles ou individus ;
* savoirs locaux non destinés à une diffusion large ;
* données recueillies pour un usage précis seulement.

### Erreur fréquente

Croire qu’une information utile doit être partagée.

Phrase clé :

> Ce qui est utile à comprendre n’est pas toujours libre à réutiliser.

## 15.3.5 Non réutilisable

### À expliquer

Un dossier peut être non réutilisable si :

* l’origine est inconnue ;
* le contexte est perdu ;
* les données sont trop incertaines ;
* les personnes concernées ne peuvent pas être consultées ;
* l’information est trop sensible ;
* le risque de mauvaise interprétation est trop élevé ;
* l’usage prévu dépasse l’autorisation initiale.

### Exemples

* témoignage sans consentement clair ;
* notes anonymes impossibles à contextualiser ;
* document contenant des informations personnelles non protégées ;
* rapport dont les conditions de production sont inconnues.

### Erreur fréquente

Penser qu’écarter un dossier est une perte.

Correction :

> Ne pas réutiliser un dossier peut être une décision responsable.

---

# 15.4 Transformer

## 15.4.1 Opération centrale

Le chapitre enseigne cette transformation :

```text
document oublié
→ origine
→ contexte
→ statut
→ limites
→ vérifications
→ potentiel d’action
```

Cette transformation s’inscrit dans la logique UCKK de transformation contrôlée : une trace ne devient pas automatiquement mémoire utile, et une mémoire ne devient pas automatiquement action. Il faut clarifier les passages. 

## 15.4.2 Étape 1 — Identifier le dossier

Questions :

* Quel est le document ou la trace ?
* Où se trouve-t-il ?
* Qui l’a produit ?
* Quand a-t-il été produit ?
* Pourquoi a-t-il été produit ?
* Qui était concerné ?
* Dans quel contexte ?

## 15.4.3 Étape 2 — Comprendre pourquoi il est dormant

Questions :

* Pourquoi ce dossier n’a-t-il pas été utilisé ?
* A-t-il été oublié ?
* Était-il trop long ?
* Était-il sensible ?
* Était-il incomplet ?
* Personne n’était-il responsable du suivi ?
* Le projet s’est-il arrêté ?
* Le contexte a-t-il changé ?

## 15.4.4 Étape 3 — Identifier ce qui semble encore utile

Questions :

* Qu’est-ce qui est encore pertinent ?
* Quelles ressources sont mentionnées ?
* Quels besoins sont nommés ?
* Quelles solutions avaient été proposées ?
* Quels obstacles avaient été repérés ?
* Quelles décisions avaient été prises ?
* Qu’est-ce qui pourrait éclairer une action actuelle ?

## 15.4.5 Étape 4 — Identifier les limites

Questions :

* Qu’est-ce qui est incertain ?
* Qu’est-ce qui est dépassé ?
* Qu’est-ce qui est sensible ?
* Qu’est-ce qui doit être validé ?
* Qu’est-ce qui ne doit pas être partagé ?
* Qui doit autoriser l’usage ?
* Quel risque existe si le dossier est mal compris ?

## 15.4.6 Étape 5 — Attribuer un statut

Attribuer un des quatre statuts :

```text
utilisable
à vérifier
sensible
non réutilisable
```

Possibilité : un même dossier peut contenir plusieurs parties ayant des statuts différents.

Exemple :

```text
Le résumé général peut être utilisable.
Les témoignages individuels sont sensibles.
Les données chiffrées sont à vérifier.
Une section sans source est non réutilisable.
```

> Avant de transformer un dossier en action, il faut reconnaître son statut.

# 15.7 Points de vigilance

## 15.7.1 Origine

Toujours demander :

* d’où vient ce dossier ?
* qui l’a produit ?
* dans quel contexte ?
* pour quel usage initial ?

## 15.7.2 Autorité

Demander :

* qui peut autoriser l’usage ?
* qui doit être consulté ?
* qui pourrait contester l’usage ?
* qui est concerné par les conséquences ?

## 15.7.3 Contexte

Demander :

* le contexte est-il encore compréhensible ?
* le contexte a-t-il changé ?
* les personnes, lieux, règles ou conditions ont-ils changé ?

## 15.7.4 Sensibilité

Demander :

* ce dossier contient-il des informations personnelles ?
* contient-il des savoirs non destinés à une diffusion large ?
* contient-il des éléments qui pourraient nuire à quelqu’un ?
* contient-il des données ou récits qui exigent une protection ?

## 15.7.5 Absences

Demander :

* qui n’apparaît pas dans le dossier ?
* quelles voix sont absentes ?
* quelles catégories imposent déjà une lecture ?
* quelles questions n’ont jamais été posées ?

Cette attention aux absences prépare le chapitre 16, où le dossier sera transformé en information actionnable.

# 1. Situer

## 1.1 Rôle du chapitre

Ce chapitre vient après l’identification d’un **savoir dormant**.

Le chapitre 15 a permis de repérer un dossier, une archive, une note, un rapport ou une expérience déjà existante. Le chapitre 16 apprend maintenant à relire ce dossier pour déterminer ce qu’il permet réellement de comprendre, vérifier, protéger ou faire.

## 1.2 Idée centrale

Lire un dossier ne suffit pas.

Un dossier peut contenir des informations utiles, mais aussi :

* des informations dépassées ;
* des interprétations discutables ;
* des absences importantes ;
* des données sensibles ;
* des erreurs ;
* des limites de contexte ;
* des pistes d’action non validées.

Phrase d’ouverture suggérée :

> Un dossier dormant ne devient pas actionnable parce qu’il existe. Il devient actionnable lorsqu’on sait ce qu’il contient, ce qui manque, ce qui doit être vérifié, ce qui doit rester protégé et ce qui peut guider une action.

## 1.3 Question directrice

La question centrale du chapitre est :

> Que permet ce dossier de comprendre, vérifier, protéger ou faire ?

## 1.4 Ce que l’étudiant doit apprendre

À la fin du chapitre, l’étudiant doit être capable de :

* résumer un dossier sans en perdre le contexte ;
* repérer les informations encore utiles ;
* distinguer information, interprétation et action possible ;
* identifier les absences ;
* évaluer les risques de réutilisation ;
* déterminer ce qui doit rester protégé ;
* formuler une piste d’action prudente.

# 2. Distinguer

## 2.1 Les distinctions essentielles

L’étudiant doit apprendre à ne pas tout traiter comme une “information utilisable”.

| Élément                    | Définition simple                                     | Question à poser                            |
| -------------------------- | ----------------------------------------------------- | ------------------------------------------- |
| Information brute          | Élément présent dans le dossier                       | Qu’est-ce que le dossier dit réellement ?   |
| Interprétation             | Sens donné à l’information                            | Qui interprète ? Selon quel contexte ?      |
| Action possible            | Geste ou décision que le dossier peut éclairer        | Que peut-on faire à partir de cela ?        |
| Information dépassée       | Élément qui n’est peut-être plus actuel               | Est-ce encore vrai ou utile ?               |
| Information sensible       | Élément qui peut exposer, blesser ou être mal utilisé | Qui peut l’autoriser ou la protéger ?       |
| Absence importante         | Voix, donnée ou contexte manquant                     | Qui ou quoi n’apparaît pas ?                |
| Risque de mauvaise lecture | Possibilité d’interpréter hors contexte               | Comment éviter une conclusion trop rapide ? |

## 2.2 Information brute ≠ action

Un dossier peut contenir une information vraie sans que cette information mène immédiatement à une action.

Exemple :

```text
Information brute :
Un rapport indique que plusieurs familles ont mentionné un problème de transport.

Interprétation possible :
Le transport est peut-être un obstacle à la participation.

Action possible :
Vérifier les horaires, les distances et les besoins actuels avant de proposer une solution.
```

## 2.3 Information disponible ≠ information partageable

Un document peut être accessible, mais contenir des éléments qui ne doivent pas circuler librement.

Questions à poser :

* Cette information est-elle publique ?
* A-t-elle été produite pour un usage précis ?
* Peut-elle être citée ?
* Peut-elle être résumée ?
* Doit-elle rester interne ?
* Qui peut autoriser sa réutilisation ?
* Quel tort pourrait être causé si elle circule hors contexte ?

## 2.4 Information ancienne ≠ information inutile

Une information ancienne peut encore être utile, mais elle doit être vérifiée.

Elle peut servir à :

* comprendre l’historique d’un problème ;
* repérer une solution déjà proposée ;
* identifier un blocage récurrent ;
* retrouver une ressource oubliée ;
* éviter de répéter une erreur.

Mais elle ne doit pas être utilisée comme si elle était automatiquement actuelle.

## 2.5 Absence ≠ absence de problème

Un dossier ne montre jamais tout.

Il faut demander :

* Qui n’apparaît pas dans ce dossier ?
* Quelles voix sont absentes ?
* Quels groupes sont mentionnés mais non entendus ?
* Quelles catégories imposent déjà une lecture ?
* Qu’est-ce qui n’a pas été documenté ?
* Qu’est-ce qui ne pouvait peut-être pas être documenté ?

## 2.6 Erreurs fréquentes

À éviter :

* résumer trop vite ;
* extraire seulement ce qui confirme une idée ;
* traiter une interprétation comme un fait ;
* ignorer la date du dossier ;
* ignorer les absences ;
* utiliser une information sensible sans permission ;
* transformer une piste ancienne en solution actuelle ;
* rendre public ce qui doit rester protégé ;
* oublier qui a produit le dossier et pour quel usage.

# 3. Transformer

## 3.1 Transformation centrale

Le chapitre apprend à transformer un dossier dormant en information actionnable.

```text
dossier existant
→ lecture prudente
→ éléments utiles
→ absences
→ risques
→ vérifications
→ protections
→ action possible
```

## 3.2 Ce qu’est une information actionnable

Une information devient actionnable lorsqu’elle peut aider à :

* mieux comprendre une situation ;
* formuler une question utile ;
* vérifier une hypothèse ;
* identifier une ressource ;
* comparer des options ;
* préparer une décision ;
* poser un premier geste ;
* éviter une erreur ;
* transmettre un apprentissage ;
* protéger une information sensible.

## 3.3 Ce qu’une information actionnable n’est pas

Une information actionnable n’est pas nécessairement :

* une solution ;
* une vérité complète ;
* une recommandation finale ;
* une autorisation d’agir ;
* une permission de partager ;
* une preuve suffisante ;
* une obligation de faire quelque chose.

Formule à intégrer :

> Actionnable ne veut pas dire immédiatement utilisable. Actionnable veut dire assez clair pour orienter une prochaine étape prudente.

## 3.4 Les cinq opérations de transformation

### 1. Résumer

Identifier ce que le dossier contient réellement.

Questions :

* De quoi parle ce dossier ?
* Qui l’a produit ?
* Quand ?
* Pour quel usage ?
* Quelles sont ses limites ?

### 2. Extraire

Repérer les éléments encore utiles.

À chercher :

* besoins exprimés ;
* ressources mentionnées ;
* contraintes ;
* pistes déjà proposées ;
* obstacles ;
* décisions passées ;
* personnes concernées ;
* questions ouvertes.

### 3. Vérifier

Identifier ce qui demande validation.

Questions :

* Est-ce encore actuel ?
* Qui peut confirmer ?
* Quelle source manque ?
* Qu’est-ce qui est incertain ?
* Qu’est-ce qui repose sur une interprétation ?

### 4. Protéger

Identifier ce qui ne doit pas être partagé ou utilisé sans permission.

Questions :

* Qu’est-ce qui est sensible ?
* Qu’est-ce qui pourrait causer un tort ?
* Qu’est-ce qui doit rester restreint ?
* Qui doit autoriser l’usage ?

### 5. Orienter

Formuler une prochaine étape responsable.

La prochaine étape peut être :

* une vérification ;
* une consultation ;
* une synthèse ;
* une carte des ressources ;
* une comparaison d’options ;
* une note de décision ;
* un plan d’action minimal ;
* une question à poser aux personnes concernées.

````markdown
## Intention du chapitre

Ce chapitre apprend à transformer une expérience en mémoire utile.

Une mémoire utile ne sert pas seulement à conserver ce qui s’est passé. Elle sert à :

- éviter de recommencer à zéro ;
- transmettre ce qui peut aider d’autres personnes ;
- protéger ce qui ne doit pas circuler ;
- garder trace des erreurs, blocages et corrections ;
- préparer une prochaine action plus éclairée.

- distinguer archive passive et mémoire active ;
- identifier ce qui doit être retenu après une action ;
````

## 1. Situer

### 1.1 La mémoire n’est pas seulement une conservation

Présenter l’idée centrale :

Une mémoire utile n’est pas seulement un endroit où l’on range des documents.
C’est une trace organisée qui aide à comprendre ce qui a été tenté, pourquoi, avec quels résultats, quelles limites et quelles précautions.

La mémoire utile répond à cinq questions :

1. Qu’avons-nous appris ?
2. Qu’est-ce qui reste incertain ?
3. Qu’est-ce qui peut être transmis ?
4. Qu’est-ce qui doit rester protégé ?
5. Quelle prochaine étape devient possible ?

### 1.2 Pourquoi les projets perdent leur mémoire

Expliquer les causes fréquentes :

* les personnes changent ;
* les documents sont dispersés ;
* les raisons des décisions ne sont pas notées ;
* les erreurs sont cachées au lieu d’être comprises ;
* les limites de partage ne sont pas indiquées ;
* les apprentissages restent dans la tête de quelques personnes ;
* les résultats sont conservés, mais pas le chemin qui y a mené.

### 1.3 Mémoire et capacité d’agir

Insister sur une idée forte :

> Une organisation ou une communauté devient plus capable lorsqu’elle peut apprendre de ce qu’elle a déjà vécu.

La mémoire utile permet de :

* reprendre un projet sans repartir de zéro ;
* éviter de répéter une erreur ;
* reconnaître ce qui a fonctionné ;
* préserver les précautions ;
* transmettre une méthode ;
* préparer une action future.

### 1.4 Lien avec les références

Graham et al. soutiennent l’idée que les connaissances doivent être transformées pour devenir utilisables dans l’action. Les principes FAIR rappellent l’importance de rendre les informations trouvables, accessibles, interopérables et réutilisables, mais dans ce cours, FAIR doit être complété par CARE et OCAP® afin de respecter l’autorité, les droits collectifs, les conditions d’accès et les limites de réutilisation. 

### Phrase de section

> La mémoire utile ne garde pas seulement les résultats. Elle garde aussi les raisons, les chemins, les limites et les corrections.

## 2. Distinguer

### 2.1 Mémoire courte et mémoire longue

| Type de mémoire | Fonction                                 | Exemple                                            |
| --------------- | ---------------------------------------- | -------------------------------------------------- |
| Mémoire courte  | Soutenir la prochaine étape immédiate    | note de suivi, décision récente, tâche à faire     |
| Mémoire longue  | Préserver l’apprentissage pour plus tard | rapport synthèse, fiche de projet, archive validée |

Expliquer :

La mémoire courte aide à poursuivre l’action.
La mémoire longue aide à transmettre l’expérience.

Les deux sont nécessaires.

---

### 2.2 Mémoire publique, restreinte et protégée

| Type de mémoire    | Description                                 | Usage possible                                                                     |
| ------------------ | ------------------------------------------- | ---------------------------------------------------------------------------------- |
| Mémoire publique   | Peut être partagée largement                | résumé, méthode, résultat général                                                  |
| Mémoire restreinte | Partagée seulement avec certaines personnes | note interne, contexte sensible, décision de groupe                                |
| Mémoire protégée   | Ne doit pas circuler sans autorisation      | savoir sensible, information personnelle, élément culturel ou communautaire limité |

Phrase clé :

> Ce qui est utile n’est pas automatiquement partageable.

Cette distinction est importante pour éviter qu’un apprentissage devienne une extraction ou une exposition involontaire.

---

### 2.3 Archive passive et mémoire active

| Archive passive                | Mémoire active                        |
| ------------------------------ | ------------------------------------- |
| Document conservé              | Trace organisée pour servir           |
| Souvent difficile à retrouver  | Facile à comprendre et reprendre      |
| Conserve un résultat           | Conserve aussi le contexte            |
| Peut rester inutilisée         | Prépare une prochaine action          |
| Ne dit pas toujours quoi faire | Indique les apprentissages et limites |

Formule :

> Une archive devient mémoire active lorsqu’elle aide quelqu’un à comprendre, décider ou agir plus prudemment.

---

### 2.4 Résultat et apprentissage

Distinguer :

* le résultat : ce qui a été produit ;
* l’apprentissage : ce qu’on comprend grâce à l’expérience ;
* la correction : ce qu’il faudra faire autrement ;
* la limite : ce qu’on ne peut pas conclure ;
* la précaution : ce qu’il faut protéger.

Exemple :

```text
Résultat : trois options ont été comparées.
Apprentissage : l’option la plus rapide n’était pas la plus responsable.
Correction : consulter plus tôt les personnes concernées.
Limite : certaines informations restent incertaines.
Précaution : ne pas partager les notes brutes.
```

---

### 2.5 Mémoire et futur

La mémoire utile n’est pas tournée seulement vers le passé.

Elle sert aussi à projeter :

* une prochaine étape ;
* une question à vérifier ;
* un risque à surveiller ;
* une ressource à mobiliser ;
* une décision à réviser ;
* un dossier à rouvrir plus tard.

Phrase de section :

> Mémoriser, ce n’est pas fermer le projet. C’est préparer le prochain cycle.

### 3.1 Transformation centrale du chapitre

### 3.2 Les six opérations de mémoire utile

L’étudiant doit apprendre à faire six opérations.

#### 1. Résumer

#### 2. Comprendre

#### 3. Limiter

#### 4. Trier

#### 6. Relier

Méthode :


Dans le standard UCKK, la mémoire n’est pas une fin. Elle est un passage.

Cela reprend la logique centrale des flows : l’action doit devenir expérience, l’expérience doit devenir mémoire, et la mémoire doit nourrir une nouvelle capacité de connaître.

## 5. Retenir

### 5.1 Points clés

* Une mémoire utile n’est pas une simple archive.
* Elle conserve les apprentissages, pas seulement les résultats.
* Elle conserve aussi les erreurs, blocages, corrections et limites.
* Tout ce qui est utile n’est pas automatiquement partageable.
* Une mémoire responsable indique ce qui peut être transmis et ce qui doit rester protégé.
* La mémoire prépare le prochain cycle d’action.

### 5.2 Erreurs fréquentes

* Garder seulement le résultat final.
* Effacer les erreurs ou les blocages.
* Ne pas noter les raisons d’une décision.
* Publier trop largement une information sensible.
* Oublier de dire ce qui reste incertain.
* Confondre archive et mémoire active.
* Ne pas indiquer qui peut réutiliser l’information.
* Produire une mémoire si vague qu’elle ne peut pas servir.

### 5.3 Points de vigilance

Avant de transmettre une mémoire, demander :

* qui pourrait être affecté par cette transmission ?
* qui devrait valider ?
* le contexte est-il suffisant ?
* les limites sont-elles visibles ?
* les incertitudes sont-elles conservées ?
* les éléments protégés sont-ils clairement séparés ?

### 5.4 Phrase à retenir

> Une mémoire utile ne conserve pas seulement les résultats. Elle conserve aussi les chemins, les erreurs, les blocages, les corrections et les limites.

### 5.5 Transition vers la Partie 5

Transition :

````markdown
## 18.1 Situer — Reprendre le chemin complet

### Idée centrale

Le travail final ne commence pas à la fin du cours.  
Il assemble tout ce qui a été construit progressivement.

Il ne s’agit pas d’ajouter une conclusion décorative. Il s’agit de montrer que l’étudiant sait relier :

```text
situation
→ ressources
→ écoute
→ compréhension
→ options
→ choix
→ impacts
→ action
→ mémoire
````

### Les neuf gestes du guide

Le guide repose sur neuf gestes :

1. identifier une situation ;
2. inventorier les ressources ;
3. écouter et observer ;
4. distinguer faits, hypothèses et interprétations ;
5. explorer plusieurs solutions ;
6. choisir sous contrainte de temps ;
7. prévoir les impacts ;
8. poser un premier geste responsable ;
9. garder une mémoire utile.

### Pourquoi cette synthèse est importante

Sans synthèse, les exercices restent séparés.

Avec une synthèse, l’étudiant peut montrer :

* comment il est passé d’une situation confuse à une compréhension structurée ;
* comment il a évité de choisir trop vite ;
* comment il a prévu les impacts ;
* comment il a transformé une information ou un dossier en ressource utile ;
* comment il garde une mémoire pour la suite.

### Phrase à retenir

> La synthèse ne résume pas seulement ce qui a été fait. Elle montre comment chaque étape a transformé la compréhension et préparé l’action.

---

## 18.2 Distinguer — Ce que le travail final doit démontrer

### Idée centrale

Le travail final n’évalue pas la capacité de trouver une solution parfaite.

Il évalue la capacité de construire une démarche prudente, traçable et révisable.

### Le travail final n’est pas

Le travail final n’est pas :

* une solution parfaite ;
* une vérité finale ;
* une analyse abstraite ;
* une collecte d’information ;
* une opinion personnelle non structurée ;
* une proposition imposée à d’autres ;
* un rapport qui efface les incertitudes ;
* une archive sans action possible.

### Le travail final est

Le travail final est :

* une démarche ;
* une transformation ;
* une trace ;
* une justification ;
* une proposition prudente ;
* une mémoire utile ;
* une base pour poursuivre.

### Distinctions importantes

| À ne pas confondre | Distinction attendue                           |
| ------------------ | ---------------------------------------------- |
| Information        | Ce qui est disponible                          |
| Connaissance       | Ce qui a été vérifié, situé ou compris         |
| Hypothèse          | Ce qui reste à confirmer                       |
| Interprétation     | Le sens donné à une situation                  |
| Choix              | L’option retenue pour maintenant               |
| Action             | Le premier geste concret                       |
| Impact             | Ce que l’action peut produire                  |
| Mémoire            | Ce qui doit être conservé, transmis ou protégé |

### Point de vigilance

L’étudiant ne doit pas effacer ce qui reste incertain.
Une bonne démarche nomme aussi ses limites.

### Phrase à retenir

> Une démarche est plus crédible lorsqu’elle montre ce qu’elle sait, ce qu’elle suppose, ce qu’elle ignore encore et ce qu’elle doit protéger.

## 18.3 Transformer — Assembler les apprentissages

### Idée centrale

Le travail final transforme les productions partielles en une seule démarche cohérente.

La transformation centrale est :

```text
situation ou dossier
→ ressources
→ écoute
→ compréhension
→ options
→ choix
→ impacts
→ action
→ mémoire
```

### Les passages à montrer

L’étudiant doit montrer les passages suivants.

#### 1. De la situation aux ressources

Montrer comment la situation choisie a été enrichie par l’inventaire des ressources.

Question :

> Qu’est-ce que j’ai découvert qui existait déjà ?

#### 2. Des ressources à l’écoute

Montrer comment l’écoute a modifié ou nuancé la première compréhension.

Question :

> Quelle parole, observation, limite ou nuance a changé ma lecture ?

#### 3. De l’écoute à la compréhension

Montrer comment l’étudiant a distingué faits, hypothèses et interprétations.

Question :

> Qu’est-ce qui est vérifié, supposé, interprété ou encore incertain ?

#### 4. De la compréhension aux options

Montrer comment plusieurs solutions ont été produites.

Question :

> Quelles options étaient possibles avant de choisir ?

#### 5. Des options au choix

Montrer pourquoi une option est retenue pour maintenant.

Question :

> Pourquoi cette option est-elle la plus responsable dans le temps disponible ?

#### 6. Du choix à l’impact

Montrer les impacts possibles.

Question :

> Qui ou quoi pourrait être affecté par cette action ?

#### 7. De l’impact à l’action

Montrer le premier geste réaliste.

Question :

> Quel geste peut être posé sans prétendre tout régler ?

#### 8. De l’action à la mémoire

Montrer ce qui doit être conservé, transmis ou protégé.

Question :

> Que faut-il retenir pour ne pas recommencer à zéro ?

### Phrase à retenir

> Le travail final est réussi lorsque les passages entre les étapes sont visibles.

## 18.6 Évaluer — Grille d’évaluation de l’enseignant

### Idée centrale

L’évaluation porte sur la qualité de la démarche, pas sur la perfection de la solution.

### Grille proposée

| Critère                                                  | Pondération |
| -------------------------------------------------------- | ----------: |
| Clarté de la situation choisie                           |        10 % |
| Qualité de l’inventaire des ressources                   |        15 % |
| Qualité de l’écoute et de l’observation                  |        15 % |
| Distinction faits / hypothèses / interprétations         |        10 % |
| Richesse de l’inventaire des solutions                   |        10 % |
| Qualité du choix justifié                                |        10 % |
| Prévision des impacts                                    |        15 % |
| Plan d’action minimal                                    |         5 % |
| Réactivation d’un dossier ou d’une information existante |         5 % |
| Mémoire utile et retour réflexif                         |         5 % |

### Note pédagogique

Le travail final peut être très bon même si la solution proposée reste modeste.
La qualité se mesure à la prudence, à la clarté, à la cohérence et à la capacité de révision.

---

## 18.7 Projeter — Après le travail final

### Idée centrale

Le travail final ne doit pas fermer la démarche.
Il doit ouvrir une suite possible.

### Questions de projection

* Quelle prochaine étape serait réaliste ?
* Qui devrait être consulté avant d’aller plus loin ?
* Quelle ressource pourrait être mobilisée ensuite ?
* Quel dossier devrait être relu ou complété ?
* Quelle information doit rester protégée ?
* Quel impact devra être surveillé ?
* Comment cette démarche pourrait-elle servir à une autre situation ?

### Production possible

Une courte section finale intitulée :

```text
Prochaine étape responsable
```

Elle contient :

* une action possible ;
* une personne ou un groupe à consulter ;
* une ressource à mobiliser ;
* un risque à surveiller ;
* une mémoire à conserver.

### Phrase à retenir

> Un bon travail final ne ferme pas le dossier. Il rend la suite plus claire.

### Idée centrale

Le travail final doit s’appuyer sur les références du guide, mais sans devenir une revue de littérature.

Les références servent à soutenir la démarche.

### Formule à utiliser dans le guide

> Les références complètes se trouvent dans la bibliographie commentée. Le travail final peut mobiliser quelques références, mais il doit surtout démontrer une démarche claire.

La bibliographie commentée soutient déjà les grands axes du guide : méthodologies autochtones, recherche non extractive, souveraineté des données, écoute, développement communautaire, décision collective, impacts et mobilisation des connaissances.

## 18.9 Retenir — Conclusion du chapitre

### Ce que cette partie doit laisser à l’étudiant

À la fin du guide, l’étudiant doit comprendre que le travail final n’est pas un exercice administratif.

C’est une démonstration de capacité :

* capacité de ralentir ;
* capacité d’écouter ;
* capacité de distinguer ;
* capacité d’explorer ;
* capacité de choisir ;
* capacité de prévoir ;
* capacité d’agir ;
* capacité de mémoriser ;
* capacité de transmettre prudemment.

### Phrase finale principale

> Le but n’est pas de produire une réponse parfaite. Le but est de produire une démarche claire, prudente, révisable et utile.

### Variante plus institutionnelle

> Ce travail final évalue la capacité de transformer une situation ou un dossier existant en piste d’action responsable, documentée et révisable.

### Variante courte

> Une démarche bien construite vaut mieux qu’une solution trop rapide.

## 18.10 Transition vers la fin du manuel

Après ce chapitre, le manuel peut se terminer par :

1. un glossaire bref ;
2. une bibliographie commentée séparée ;
3. une page finale de synthèse ;
4. une invitation à réutiliser la méthode dans d’autres contextes.

### Dernier paragraphe possible

Ce guide propose une manière de passer d’une situation confuse à une action responsable. Il ne demande pas de tout savoir, ni de tout résoudre. Il demande d’apprendre à reconnaître les ressources, écouter avec attention, distinguer ce qui est sûr de ce qui doit être vérifié, explorer plusieurs solutions, choisir avec prudence, prévoir les impacts et garder une mémoire utile. C’est cette capacité qui permet de ne pas recommencer à zéro et de transformer les savoirs en possibilités d’action.
