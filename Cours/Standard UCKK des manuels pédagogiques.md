# Standard UCKK des manuels pédagogiques

## Statut

**Standard fixé — version de travail 0.1**

Ce standard servira de modèle commun pour les manuels UCKK, peu importe le cours ou le baccalauréat. Il donne une structure reconnaissable, tout en laissant assez de souplesse pour les cours théoriques, méthodologiques, techniques, communautaires ou créatifs.

---

# 1. Formule maîtresse

> **Un manuel UCKK ne transmet pas seulement du contenu. Il guide une transformation : il situe une question, distingue ce qui doit l’être, donne une méthode, fait produire un livrable, conserve une trace et ouvre un futur possible.**

Version courte :

> **Un manuel UCKK transforme des savoirs en capacité d’agir.**

Cette formule reprend la logique centrale de tes flows : la valeur n’est pas seulement dans les catégories, mais dans les **passages contrôlés** entre matière, compréhension, choix, action et mémoire. Le document sur le kOA Digital Ecosystem insiste justement sur le fait qu’une contribution ne devient pas automatiquement connaissance, qu’une connaissance ne devient pas automatiquement choix, qu’un choix ne devient pas automatiquement action, et qu’une action ne devient pas automatiquement mémoire. Chaque passage demande une structure, un seuil, une trace ou une interface. 

---

# 2. Standard général UCKK

Le standard commun des manuels est :

```text
Orienter
→ Situer
→ Distinguer
→ Transformer
→ Produire
→ Évaluer
→ Mémoriser
→ Projeter
→ Référencer
```

## Version développée

| Étape              | Fonction                                      | Question centrale                                            |
| ------------------ | --------------------------------------------- | ------------------------------------------------------------ |
| **0. Orienter**    | Donner le mandat du manuel                    | Pourquoi ce manuel existe-t-il ?                             |
| **1. Situer**      | Présenter les héritages, auteurs et contextes | D’où vient cette question ?                                  |
| **2. Distinguer**  | Clarifier les concepts et confusions à éviter | Que faut-il ne pas confondre ?                               |
| **3. Transformer** | Enseigner l’opération centrale du cours       | Quelle transformation l’étudiant doit-il apprendre à faire ? |
| **4. Produire**    | Faire créer un livrable                       | Que doit produire l’étudiant ?                               |
| **5. Évaluer**     | Vérifier la qualité du travail                | Selon quels critères juge-t-on la production ?               |
| **6. Mémoriser**   | Garder trace et rendre réutilisable           | Que faut-il retenir, transmettre ou protéger ?               |
| **7. Projeter**    | Ouvrir vers les futurs possibles              | Qu’est-ce qui émerge ? Que faut-il surveiller ?              |
| **8. Référencer**  | Relier aux sources                            | Sur quoi s’appuie le manuel ?                                |

# 3. Pourquoi ce standard remplace “passé / présent / futur”

L’axe :

```text
passé → présent → futur
```

reste utile, mais il est incomplet pour un manuel pédagogique.

Il permet de dire :

```text
d’où ça vient → où on est → où ça va
```

Le standard UCKK ajoute les opérations nécessaires à l’apprentissage :

```text
d’où ça vient
→ ce qu’il faut distinguer
→ ce qu’il faut transformer
→ ce qu’il faut produire
→ ce qu’il faut évaluer
→ ce qu’il faut mémoriser
→ ce qu’il faut projeter
```

Donc le passé / présent / futur devient une composante du standard :

| Ancienne intuition  | Nouvelle fonction UCKK         |
| ------------------- | ------------------------------ |
| Passé               | Situer                         |
| Présent             | Distinguer / Transformer       |
| Futur               | Projeter                       |
| Travail pédagogique | Produire / Évaluer / Mémoriser |

# 5. Standard de chapitre UCKK

Chaque chapitre doit suivre une structure commune.

```text
Situer
→ Distinguer
→ Transformer
→ Produire
→ Retenir
→ Référencer
```

## Modèle de chapitre

```markdown
# Chapitre X — Titre

## 1. Situer

D’où vient cette question ?  
Quels auteurs, pratiques, traditions, contextes ou problèmes historiques l’éclairent ?

## 2. Distinguer

Quelles confusions faut-il éviter ?  
Quels concepts doivent être séparés ?  
Quelles limites faut-il reconnaître ?

## 3. Transformer

Quelle opération l’étudiant doit-il apprendre à faire ?  
Exemples : transformer une observation en carte, une hypothèse en question, une solution en choix justifié, une action en mémoire utile.

## 4. Produire

Quel tableau, fiche, carte, note, décision, plan ou livrable l’étudiant doit-il produire ?

## 5. Retenir

Phrase clé.  
Erreurs fréquentes.  
Points de vigilance.

## 6. Références mobilisées

Références courtes.  
Voir la bibliographie commentée pour les références complètes.
```

# 6. Standard d’exercice UCKK

Chaque exercice doit aussi suivre une forme stable.

```text
Entrée
→ Consigne
→ Production
→ Critères
→ Trace
```

## Modèle d’exercice

```markdown
# Exercice X — Titre

## Entrée

Quelle matière l’étudiant reçoit-il ?  
Exemple : situation, texte, cas, témoignage, document, problème, dossier dormant.

## Consigne

Que doit-il faire exactement ?

## Production attendue

Quel livrable doit-il remettre ?

## Critères de réussite

Comment saura-t-on que le travail est réussi ?

## Trace à conserver

Qu’est-ce qui doit rester dans la mémoire du projet ?
```

Ce modèle est cohérent avec l’idée de **runtime pédagogique** : le manuel ne donne pas seulement du contenu, il organise des rôles, des opérations, des livrables, des critères et des traces. Cette idée rejoint le texte sur le Sociotechnical OS, qui définit un système opérable comme une combinaison de rôles, permissions, protocoles, règles d’intégrité, workflows de responsabilité et auditabilité.

# 7. Invariants pédagogiques UCKK

Tous les manuels doivent respecter ces invariants.

```text
1. Ne pas confondre information et connaissance.
2. Ne pas confondre hypothèse et vérité.
3. Ne pas confondre opinion et choix justifié.
4. Ne pas confondre décision et action.
5. Ne pas confondre action et impact.
6. Ne pas confondre archive et mémoire utile.
7. Ne pas confondre production étudiante et vérité finale.
8. Ne pas effacer les incertitudes.
9. Ne pas publier ou réutiliser sans contexte.
10. Garder une trace des raisons, limites et corrections.
```

Ces invariants sont l’équivalent pédagogique des invariants techniques présents dans tes flows : validation, traçabilité, seuils, préservation de l’ambiguïté, distinction entre proposition et vérité stabilisée, et feedback non mutant.

# 8. Les cinq modèles spécialisés

Le standard commun reste le même, mais les cours n’ont pas tous la même forme. Il faut donc cinq modèles spécialisés.

## Modèle A — Méthodologique

Pour les cours d’enquête, cartographie, recherche, décision ou intervention.

```text
Situation
→ Concepts
→ Méthode
→ Exercices
→ Production
→ Évaluation
→ Mémoire
```

Exemple : **Des savoirs à l’action**.

---

## Modèle B — Théorique / historique

Pour philosophie, politique, économie, métaphysique, linguistique, histoire des institutions.

```text
Héritages
→ Concepts
→ Débats
→ Applications
→ Critiques
→ Futurs
→ Travail final
```

---

## Modèle C — Technique / infrastructure

Pour IA gouvernable, architecture sociotechnique, systèmes, données, workflows, protocoles.

```text
Problème
→ Architecture
→ Composants
→ Protocoles
→ Tests
→ Risques
→ Cas d’usage
→ Documentation
```

Ce modèle doit être plus procédural. Il est proche de la logique “system of systems” décrite dans les documents sur l’écosystème kOA et le Sociotechnical OS : les composants indépendants doivent être intégrés dans un cycle opérable, avec interfaces, frontières, auditabilité et continuité. 

---

## Modèle D — Intervention sociale / communautaire

Pour dignité, écoute, ressources, accompagnement, institutions d’aide, action collective.

```text
Posture
→ Situation
→ Ressources
→ Écoute
→ Options
→ Choix
→ Impacts
→ Suivi
→ Mémoire
```

C’est le modèle principal de **Des savoirs à l’action**.

---

## Modèle E — Créatif / médias vivants

Pour théâtre public, récit, performance, mobilisation, symboles, médias vivants.

```text
Intention
→ Références
→ Public
→ Dispositif
→ Effets
→ Risques
→ Production
→ Retour critique
→ Mémoire
```

# 11. Règles de rédaction pour les manuels UCKK

## À faire

* Donner une orientation claire.
* Nommer les auteurs et héritages utiles.
* Présenter les problèmes actuels.
* Clarifier les distinctions importantes.
* Enseigner une transformation.
* Faire produire des livrables.
* Inclure des exercices.
* Évaluer avec des critères explicites.
* Garder une mémoire utile.
* Ouvrir vers les futurs possibles.
* Relier à une bibliographie commentée.

## À éviter

* Accumuler du contenu sans méthode.
* Réduire le manuel à une revue de littérature.
* Réduire le manuel à des exercices sans contexte.
* Confondre opinion, hypothèse et connaissance.
* Donner l’impression que la production finale est une vérité définitive.
* Effacer les incertitudes.
* Multiplier les termes internes si le public n’en a pas besoin.
* Imposer le même modèle à tous les types de cours sans adaptation.

# 13. Conclusion

Ce standard donne à l’UCKK une signature pédagogique claire.

Il ne s’agit pas seulement d’un format de manuel.
Il s’agit d’un modèle de transformation des savoirs.

Chaque manuel doit aider l’étudiant à passer :

```text
matière confuse
→ distinctions claires
→ méthode
→ production
→ évaluation
→ mémoire
→ futur possible
```

Phrase finale du standard :

> **Un manuel UCKK transforme une question en capacité : capacité de comprendre, de distinguer, de produire, d’agir, de retenir et de projeter.**
